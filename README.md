# SettingManager

Setting에 관련된 Agent 들을 관리하는 Agent.
카메라(실기 Hucoms · 시뮬레이터)를 하나의 제어면으로 묶어 **웹 콘솔**과 **REST API**로 노출한다.

---

## 1. 빠른 시작

```bash
cd SettingMain
npm install
npm start
```

기동하면 콘솔에 접속 주소가 찍힌다.

```
SettingManager  http://127.0.0.1:13030/
  설정 파일     ...\SettingMain\config\config.json
  활성 카메라   real-camera-1
```

### 접속 URL

| 화면 | URL |
|---|---|
| **카메라 제어** | <http://127.0.0.1:13030/> |
| **옵션** | <http://127.0.0.1:13030/options> |
| 상태 확인(JSON) | <http://127.0.0.1:13030/api/health> |

> 기본 바인드는 **`127.0.0.1`(이 PC에서만 접속)** 이다.
> 다른 PC에서 접속하려면 `config/config.json` 의 `server.host` 를 `"0.0.0.0"` 으로 바꾸고 재기동한 뒤
> `http://<이 PC의 IP>:13030/` 로 들어간다. 인증이 없으므로 사내망에서만 열 것.

### 사전 요구사항

| 항목 | 용도 | 확인 |
|---|---|---|
| Node.js 20 이상 | 런타임 | `node --version` |
| **ffmpeg** (PATH) | RTSP → MJPEG 전사 | `ffmpeg -version` |

ffmpeg 가 없으면 서버는 정상 기동하지만 **RTSP 카메라의 영상만** 안 나온다(그 외 기능은 모두 동작).

## 2. 화면 사용법

### 2.1 카메라 제어 (`/`)

| 영역 | 사용법 |
|---|---|
| **대상 선택** | 카메라 콤보에서 조작할 카메라를 고른다. 선택은 즉시 저장되어 다음 기동에도 유지된다. |
| **프리셋** | 콤보에서 고르고 「이동」. <br>「새 프리셋」 = 이름을 적고 **현재 PTZ**를 그 이름으로 저장. <br>「이름·PTZ 저장」 = 선택된 프리셋을 현재 이름·현재 PTZ로 덮어쓰기. <br>「삭제」 = 선택된 프리셋 삭제(확인 후). |
| **현재 PTZ** | Pan·Tilt 는 도(°), Zoom 은 raw 눈금. 아래줄에 장비 원시값 P/T/Z 를 그대로 표시. 「현재 PTZ 불러오기」로 다시 읽는다. |
| **PTZ 제어** | ▲▼◀▶ 로 팬·틸트, `+zoom`/`−zoom` 으로 줌. `step` 은 pan·tilt 에서 **도(°)**, zoom 에서 raw 눈금(×100)이다. 「중지」는 현재 자세를 다시 읽는다. |
| **절대 좌표 이동** | pan·tilt·zoom 을 raw 로 넣고 「이동」. 「현재값 채우기」로 지금 좌표를 세 칸에 넣을 수 있다. 도달범위 밖 값은 잘리고 **어느 축이 잘렸는지 하단 상태줄에 표시**된다. |
| **영상** | 「시작」을 눌러야 영상을 받는다(페이지를 여는 것만으로 카메라를 점유하지 않음). 「스냅샷 1장」은 정지 이미지 한 장만 받는다. |
| **주차면 리스트** | 시뮬레이터 카메라는 씬에서, 실카메라는 `config/slots.json` 에서 읽는다. 제목 옆 배지가 출처를 표시한다. |

오류·결과는 **화면 왼쪽 아래 상태줄**에 뜬다. 조용히 실패하는 경로는 없다.

### 2.2 옵션 (`/options`)

카드 3개가 한쪽 컬럼에 쌓인다. **저장 버튼이 카드마다 따로**여서, 누른 카드의 내용만 저장된다.

| 카드 | 사용법 |
|---|---|
| **시뮬레이터** | baro_calory `backend-core` 주소(예: `http://127.0.0.1:8080`). 타입이 *시뮬레이터*인 기기가 이 주소를 쓰고, 주차면 목록도 여기서 조회한다. 「시뮬레이터 URL 저장」으로 저장. |
| **기기 (장치)** | 콤보박스에서 카메라를 고르면 **아래 편집 카드에 그 기기의 설정만** 뜬다. 「이 기기를 활성으로」를 누르면 카메라 제어 페이지가 그 기기를 쓴다. 아래쪽 **새 기기 ID + 타입 → 「+ 기기 추가」** 로 기기를 등록한다. |
| **기기 편집: `<id>`** | 이름 · 타입 · 제어 URL · 계정/비밀번호 · 영상 URL · 타임아웃을 고치고 **「이 기기 적용」**. 「연결 테스트」·「되돌리기」·「삭제」도 여기 있다. |

동작 규칙:

- **「이 기기 적용」을 누르면 `config/config.json` 이 즉시 갱신된다**(재기동 불필요). 선택한 기기 한 건만 바뀌고 나머지 설정은 손대지 않는다.
- **「연결 테스트」는 저장 없이** 지금 화면의 값(URL·계정 등)으로 PTZ 를 한 번 읽어 본다. 카메라를 **움직이지 않는다.** 성공하면 소요 시간과 PTZ 를, 실패하면 사유를 버튼 아래에 표시한다.
- **「+ 기기 추가」는 ID 와 타입만 정하면 등록된다.** 접속 정보는 등록 후 편집 폼에서 채운다. ID 는 경로·URL 에 그대로 들어가므로 영문·숫자로 시작하고 `_ - .` 만 허용하며, **나중에 바꿀 수 없다**.
- **「삭제」는 그 기기의 프리셋도 함께 지운다**(없는 기기를 가리키는 프리셋을 남기지 않기 위해). 활성 기기를 지우면 남은 첫 기기로 활성이 옮겨 가고, **마지막 한 대는 지울 수 없다**.
- **비밀번호는 화면으로 돌아오지 않는다.** 비워 두면 **기존 비밀번호가 유지**되고, 바꿀 때만 입력한다. 저장 여부는 입력칸 안내문(`(저장됨 · 변경 시에만 입력)`)으로 표시된다.
- 저장하지 않은 편집이 있으면 카드 머리글에 **「저장 안 됨」** 배지가 뜨고, 다른 기기로 옮기려 하면 확인을 묻는다.
- 타입이 *시뮬레이터*면 계정 칸이 비활성된다(backend-core 는 계정을 쓰지 않는다). 제어 URL 을 비우면 위의 시뮬레이터 URL 을 쓴다.
- **영상 URL 은 스킴이 경로를 가른다** — `rtsp://` 는 ffmpeg 전사, `http://` 는 연속 MJPEG 중계(UE 시뮬 직결 포트), 비우면 스냅샷 폴링. 입력하는 즉시 어느 경로로 갈지 아래에 표시된다.
- **UE 시뮬은 제어 포트와 영상 포트가 1:1 짝이다** — `영상 = 제어 + 10`(8081↔8091). 짝이 어긋나면 **다른 카메라 화면**을 보게 되어 PTZ 숫자는 바뀌는데 그림은 그대로다. 옵션 페이지가 이 경우 경고한다.

## 3. 설정 파일

전부 `SettingMain/config/` 아래에 있다.

| 파일 | 내용 | 누가 쓰나 |
|---|---|---|
| **`config.json`** | 서버 포트 · 시뮬레이터 URL · 스트리밍 옵션 · **카메라 기본정보** | 옵션 페이지가 갱신. **실 IP·계정이 들어가므로 커밋하지 않는다**(`.gitignore`) |
| `config.example.json` | 초기 예시 사본 | 사람이 참고 |
| `presets.json` | 프리셋(이름 + PTZ) | 제어 페이지가 갱신 |
| `slots.json` | 실카메라 주차면 목록 | 사람이 편집(읽기 전용) |

### `config.json` 카메라 항목

```json
{
  "id": "real-camera-1",
  "label": "리얼 카메라 1",
  "kind": "hucoms",
  "controlUrl": "http://<카메라IP>:80",
  "username": "<계정>",
  "password": "<비밀번호>",
  "streamUrl": "rtsp://<카메라IP>:554/stream1",
  "timeoutMs": 5000
}
```

| 필드 | 설명 |
|---|---|
| `kind` | `hucoms` = 실카메라(HTTP CGI 직접 제어) · `backend-core` = 시뮬레이터(baro_calory REST 경유) |
| `controlUrl` | 제어 주소. `backend-core` 종류에서 비워 두면 전역 시뮬레이터 URL 을 쓴다 |
| `streamUrl` | 영상 URL. `rtsp://`=ffmpeg 전사 · `http://`=MJPEG 중계 · 비움=스냅샷 폴링. 옛 이름 `rtspUrl` 도 읽는다 |

## 4. REST API

카메라를 고르지 않으면 활성 카메라가 대상이다(`?cameraId=` 로 지정 가능).

| 메서드 · 경로 | 설명 |
|---|---|
| `GET /api/health` | 상태 |
| `GET /api/cameras` | 카메라 목록 (비밀번호 제외) |
| `POST /api/cameras` | `{ id, kind?, ... }` 기기 추가 (중복 ID → 409) |
| `DELETE /api/cameras/:id` | 기기 삭제 (프리셋 동반 삭제 · 마지막 1대 → 409) |
| `POST /api/cameras/:id/test` | 연결 테스트. `{ camera }` 를 주면 **저장 없이** 그 값으로 시험. 실패도 `200 { ok:false, error }` |
| `POST /api/cameras/active` | `{ id }` 활성 카메라 전환 |
| `GET /api/ptz` | 현재 PTZ — `{ pan, tilt, zoom, panDeg, tiltDeg }` |
| `POST /api/ptz/absolute` | `{ pan, tilt, zoom, speed? }` 절대 이동. 응답에 `limited[]` |
| `POST /api/ptz/nudge` | `{ axis, delta }` 상대 이동 (`axis`: `pan`·`tilt`·`zoom`, `delta`: raw) |
| `GET /api/presets` | 프리셋 목록 |
| `POST /api/presets` | `{ name, ptz? }` 추가 — `ptz` 생략 시 **현재 자세** 저장 |
| `PUT /api/presets/:id` | `{ name?, ptz? }` 수정 |
| `DELETE /api/presets/:id` | 삭제 |
| `POST /api/presets/:id/goto` | 프리셋으로 이동 |
| `GET /api/slots` | 주차면 목록 + `source`(`simulator`·`local`) |
| `GET /api/snapshot` | JPEG 1장 |
| `GET /api/stream` | multipart MJPEG 연속 영상 |
| `GET /api/settings` · `PUT /api/settings` | 옵션 조회 · 저장 |

### 확인 예시

```bash
curl http://127.0.0.1:13030/api/health
curl http://127.0.0.1:13030/api/ptz
curl -o snap.jpg http://127.0.0.1:13030/api/snapshot
```

## 5. 좌표 규약

계약 좌표는 Hucoms 논리 좌표계다.

| 축 | 범위 | 단위 |
|---|---|---|
| `pan` | 0 ~ 35999 | 0.01° (원 — 넘으면 감긴다) |
| `tilt` | −2000 ~ 9000 | 0.01° (범위 밖은 잘린다) |
| `zoom` | 0 ~ 65535 | **불투명 raw** |

**줌은 배율·화각으로 환산하지 않는다.** 환산에는 기기별 실측 화각표(`zoomHfov`)가 필요하고, 그 표는
캘리브레이션의 산출물이다. 모르는 값을 지어내지 않기 위해 화면은 줌을 raw 로만 표시한다.

## 7. 트러블슈팅

| 증상 | 원인·조치 |
|---|---|
| 브라우저가 안 열림 | 서버가 떠 있는지 확인(`curl http://127.0.0.1:13030/api/health`). 포트를 바꿨다면 `config.json` 의 `server.port` 확인 |
| 다른 PC에서 접속 안 됨 | 기본 바인드가 `127.0.0.1` 이다. `server.host` 를 `"0.0.0.0"` 으로 바꾸고 재기동 |
| 영상이 안 나옴 (RTSP 카메라) | `ffmpeg -version` 확인 → PATH 등록. 옵션 페이지에서 RTSP URL·계정 확인. 다른 프로그램이 같은 RTSP 세션을 쓰고 있으면 프레임이 안 올 수 있다 |
| 영상이 안 나옴 (시뮬레이터) | 옵션 페이지의 시뮬레이터 URL 확인. baro_calory `backend-core` 가 떠 있어야 한다 |
| `스냅샷이 JPEG 가 아닙니다` | 카메라 계정·권한 문제. 옵션 페이지에서 ID/Password 재입력 |
| `카메라 통신 실패` | IP·포트 도달 여부 확인. 응답도 거부도 없이 매달리면 `timeoutMs` 를 늘려 본다 |
| `카메라가 오류를 반환했습니다` | 카메라의 API 제어 활성화(`apictrlstatus`) 여부와 admin 계정인지 확인 |
| 이동 후 표시값이 목표와 다름 | ① 응답의 `limited` 축이면 도달범위에서 잘린 것 ② `settled:false`(「아직 이동 중입니다」)면 10초 안에 안 멈춘 것 — 「현재 PTZ 불러오기」로 다시 읽는다 |
| PTZ 숫자는 바뀌는데 **화면이 안 바뀜** | 제어 URL 과 영상 URL 이 **다른 카메라**를 가리키고 있다. UE 시뮬은 `영상 = 제어 + 10` 이다 |
| 저장했는데 값이 안 바뀜 | 브라우저가 옛 화면을 들고 있을 수 있다 — **Ctrl+F5** 로 새로고침한다 |
| 한글이 깨져 저장됨 / 400 `UTF-8 이 아닙니다` | 요청 본문이 UTF-8 이 아니다. CLI 로 보낼 때는 UTF-8 파일에 담아 `--data-binary @file` 로 보낸다 |
| 저장했더니 카메라 접속이 안 됨 | 옵션 페이지에서 비밀번호를 **일부러 바꾼 게 아니면 비워 두어야** 기존 값이 유지된다 |
