## 1. 한 줄 요약

### 3-1. 패널이 껍데기에 주는 계약 (새 항목 4개)

```js
return {
  isWorkMode: work.isOn,        // 메인 뷰 안내가 「누가 키보드를 갖고 있나」를 말할 때 쓴다
  onKey: work.onKey,            // true 를 주면 껍데기가 preventDefault 하고 메인 뷰로 안 넘긴다
```

## 4. ⚠ 다음에 손대야 할 것 — **언리얼 시뮬레이터 버그 3건**

셋 다 `preset.*` 이고 **셋 다 조용하다**(오류를 안 줘서 부른 쪽이 성공한 줄 안다).
전부 라이브 `192.168.0.125:13510` 실측이다. 상세: `_workspace/simtool-workmode/03_simulator_bugs.md`

### B2 — `preset.create` 가 전부 `idx:1` 로 만든다 🔴 **최우선. 지시 3을 막고 있다**

```
파일 6건 → 「시뮬로 보내기」 → preset.list 6건인데 전부 "idx": 1
preset.get {idx:2}..{idx:7} → -32000 "프리셋 없음"
```

`preset.move`·`rotate`·`select`·`delete` 가 전부 `idx` 로 대상을 지목한다.
idx 가 유일하지 않으면 **첫 번째 말고는 손댈 수 없다.**
**웹에서 우회 불가** — 서버가 준 idx 가 전부 같으면 무엇을 고르든 같은 것을 가리킨다.

→ **언리얼이 `preset.create` 에서 고유 idx 를 매기고 반환해야 한다.**
   이것만 고쳐지면 웹은 **한 줄도 안 바꿔도** 6건 전부에 Ctrl+클릭이 된다.

### B3 — `preset.create` 가 `presetName` 을 무시한다 🟡

보낸 이름 `Preset 1..6` → 저장된 이름 `Preset 6, Preset 1, Preset 1, Preset 1, Preset 1, Preset 1`.
좌표·면수·크기는 **정확히 반영된다**. B2 와 겹치면 목록에서 구별할 단서가 사라진다.

### B1 — `preset.move {delta}` 가 성공을 주고 아무것도 안 한다 🟢 **웹은 우회 완료**

```
preset.move {idx:1, delta:{x:0,y:5}} → {ok:true, x,y,z}   ← 그런데 좌표가 그대로다
preset.move {idx:1, to:{x:-16.2,y:25}} → 정상 반영
```

웹은 `preset.get` 으로 지금 자리를 읽어 `to` 로 보내 우회했다(`movePreset`).
**언리얼도 고치는 것이 맞다** — `{ok:true}` 를 주면서 아무것도 안 하는 응답이 가장 나쁘다.

## 5. 다음 세션이 알아야 할 함정

1. **`delta` 를 다시 쓰지 말 것.** 프리셋 이동은 반드시 `movePreset()` 을 거친다.
   테스트 `프리셋 이동은 to 로 보낸다` 가 이것을 지킨다.
2. **이동 축은 월드다.** 화면 기준으로 바꾸려면 yaw 삼각함수가 필요한데 **테스트가 금지**한다
   (`Math.(tan|atan2?|cos|sin)` · `yaw` 금지). 규칙은 서버 한 곳(`src/sim/simProject.ts`)이다.
3. **카메라 탭만 이동(m)과 회전(°)의 단위가 다르다** — `camMoveStep` / `camStep`.
   한 칸으로 합치면 2° 를 돌리려던 사람이 카메라를 2m 옮긴다.
4. **`preset.get` 응답의 `offsetPos` 는 이미 RPC 계다.** 이름이 파일 필드와 같을 뿐이다
   (`/api/sim/rpc` 는 그대로 통과시킨다). 테스트가 `offsetPos:`(키로 **쓰기**)만 막는다.
5. **키는 `event.code`** 로 본다 — `event.key` 면 한글 입력 상태에서 WASD·QE 가 통째로 죽는다.
6. **전체 회귀 20건 실패는 기존 것**이다(`server.test.ts` 17 · `park3dRpcServerRoutes` 2 ·
   `powershellSafeDiagnostic` 1). 이번 작업과 무관하며 stash 후 재실행해 확인했다.

## 6. 라이브 검증 절차 (다음에도 그대로 쓰면 된다)

```
1) 서버   http://localhost:13030/simtool.html
2) 시뮬   http://192.168.0.125:13510/rpc   {"jsonrpc":"2.0","id":1,"method":"system.health"}
3) 시작 전 상태를 반드시 먼저 적어 둘 것 — view.get · cam.get · car.list 수 · preset.list
4) 조작 뒤에는 화면 숫자가 아니라 **시뮬레이터에 직접 물어** 대조할 것
5) 끝나면 원상복구 + 영상 스트림 정지(slots:1 이라 남의 화면을 막는다)
```

**⚠ 「시뮬로 보내기」는 `preset.clear` 로 시작한다** — 위젯으로 그린 주차면이 있으면
되돌릴 수 없다. 프리셋 검증이 필요하면 **마스터 허락을 먼저 받을 것.**
(이번에는 마스터가 `SettingMain/save/3D/Preset/001_Preset_office.json` 을 지목해 주었다.)

**폴대는 검고 가늘다.** 넓은 화각에서는 배경과 구별되지 않는다 — 확인하려면 `view.set {fov:45}`
정도로 좁히고 가까이서 볼 것. (1차에서 이것 때문에 "폴대가 없다"고 잘못 보고했다.)

## 7. 아직 안 한 것 (지시 범위 밖)

- **거리 측정 탭은 클릭을 받지 않는다.** `measure.setTargetPoint` 에 픽 좌표를 넘기면 되지만
  1차 지시에 없었다. 화면이 "아직 클릭을 받지 않습니다"라고 그대로 말한다.
- **위아래(Z) 전용 키 없음.** 필요하면 `R`/`F` 를 더하면 된다.
- **조명 탭은 여전히 안내만** 있다 — 언리얼에 `light.*` 가 없다.
- **작업모드는 탭을 옮겨도 켜진 채로 남는다.** 체크박스가 그 탭에 보이므로 숨은 상태가 아니고,
  껍데기는 활성 탭의 것만 물어보므로 다른 탭에 영향이 없다. 의도된 동작이다.
