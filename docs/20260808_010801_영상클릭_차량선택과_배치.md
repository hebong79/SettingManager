# 영상 클릭으로 차량 선택·배치 (마스터 지시 "2.3번")

작성 2026-08-08 01:08 · 대상 `SettingMain` · 브랜치 `main`

---

## 1. 요청과 범위

마스터 질문 "스트리밍된 차량을 클릭해서 선택하고 좌우 이동 회전등을 할 수 있나?" 에 대해 세 단계를
제시했고, 마스터가 **2·3번을 지시**했다.

| 단계 | 내용 | 이번 작업 |
|---|---|---|
| 1 | 방향 패드로 즉시 이동·회전 | 지시 없음 — 하지 않음 |
| **2** | **영상 클릭 → 목록에서 그 차 선택** | ✅ |
| **3** | **영상 클릭 → 그 지면 좌표에 차 배치** | ✅ |

3번은 처음에 "언리얼에 `view.pick` 또는 `cam.project` 가 필요하다"고 보고했으나,
**화각 상수 하나를 실측하니 기존 RPC만으로 성립**했다. 언리얼 서버는 손대지 않았다.

## 2. 이 작업의 실체는 상수 하나를 재는 일이었다

클릭을 월드 좌표로 바꾸려면 카메라의 위치·방향·화각이 필요하다. 앞의 둘은 `cam.get` 이 주지만
**화각을 읽는 RPC 는 82개 중에 없다**(`cam.setFOV` 는 쓰기 전용).

### 2-1. 쓰기와 읽기를 엮어 역산했다

`cam.setFOV(F)` 로 화각을 넣고 `cam.getPTZ` 로 줌을 읽으면 `zoom = tan(H₁/2)/tan(F/2)` 이므로
`H₁ = 2·atan(zoom·tan(F/2))` 다.

| 넣은 FOV | 읽힌 zoom | 역산 H₁ |
|---:|---:|---:|
| 80.0° | 1.00000 | (무효 — 줌 하한 1에 걸림) |
| 60.0° | 1.00000 | (무효 — 같음) |
| 45.0° | 1.29720 | **56.500°** |
| 30.0° | 2.00530 | **56.500°** |
| 20.0° | 3.04729 | **56.500°** |

세 점이 소수점까지 같다. 80°·60° 가 zoom 1 로 눌린 것은 **그보다 넓어질 수 없다**는 뜻이라
오히려 56.5° 를 뒷받침한다.

### 2-2. "설정값"이 아니라 "렌더되는 값"임을 영상으로 확인했다

같은 장면을 tilt 만 2° 옮겨 두 장 찍고 세로 이동량을 재면 세로 화각이 나온다.

| zoom | 이동량 | 실측 VFOV | 식이 주는 값 |
|---:|---:|---:|---:|
| 2.4 | 100px / 720 | 14.33° | 14.36° |
| 6.0 | 250px / 720 | 5.76° | 5.77° |

덤으로 **`setFOV` 의 fov 가 가로**임도 정해졌다 — 세로였다면 zoom 2.4 에서 25.2° 가 나왔어야 한다.

## 3. 크게 속을 뻔한 함정 — `measure.angles` 는 pan 과 기준이 다르다

`measure.setTargetPoint` + `measure.angles` 로 알려진 차의 각도를 재고 내 계산과 맞춰 보니
**수직은 오차 0.000°, 수평은 정확히 26.562° 어긋났다.** 상수 오프셋이라 "기준만 다르다"고 보고
그 값을 카메라 설치 yaw 로 채택했다 — 그리고 **틀렸다.**

pan 을 0·30·47.1·90·180·−90 으로 돌려 가며 다시 재 보니 `measure.angles.horizontal` 은
**pan 과 무관하게 −14.466° 로 고정**이었다. 곧 그것은 화면 기준 각도가 아니라 카메라
**설치 기준**의 절대 방향이고, `pan` 의 0° 와는 다른 축이다.

진짜 관계는 훨씬 단순했다:

```
pan = atan2(dy, dx)      (월드 방위각, 도)
tilt = atan2(-dz, √(dx²+dy²))   (양수가 하향)
```

즉 **설치 yaw 보정은 애초에 필요 없었다.**

이 오류가 위험했던 이유는 붐비는 주차장에서는 20° 를 틀려도 **여전히 차가 보이기 때문**이다.
줌 6배로 조준했더니 화면에 차가 하나 있었고, 나는 그것을 "맞았다"고 읽었다. 실제로는 다른 차였다.

**바로잡은 방법:** 좌표계 가설 8가지 × 기준 yaw 5가지를 전부 대입해 "화면 1280×720 안에 들어오는
차량 수"를 세고, 실제 영상에 보이는 8대와 맞는 조합을 찾았다. `raw(x,y,z)` + `yaw 0` 만 8을 냈다.
그 뒤 **줌 10배(화각 6.2°)** 로 조준해 확정했다 — 그 좁은 화각에서는 2° 만 틀려도 차가 화면에서
사라지므로 우연히 맞을 수 없다.

## 4. 확정된 카메라 모델

`SettingMain/src/sim/simProject.ts` 한 곳에만 있다.

```
yaw  = pan (도)               ← 월드 방위각 그대로
tilt = tilt (도)              ← 양수가 하향
tanH = tan(56.5°/2) / zoom
tanV = tanH × height / width

[월드 → 화면]
 e1 =  dx·cos(yaw) + dy·sin(yaw)
 e2 = -dx·sin(yaw) + dy·cos(yaw)
 fwd = e1·cos(tilt) - dz·sin(tilt)      (≤0 이면 카메라 뒤 → null)
 up  = e1·sin(tilt) + dz·cos(tilt)
 x = ( (-e2/fwd)/tanH + 1 ) / 2 × width
 y = ( 1 - (up/fwd)/tanV ) / 2 × height

[화면 → 지면 z=groundZ]  위 회전을 그대로 역으로 풀고 평면과 교차시킨다.
```

좌우 부호는 독립 검증했다 — pan 을 +3° 돌리니 영상 내용이 **오른쪽으로 132px** 갔다.
곧 pan 을 키워야 중앙에 오는 대상은 그전에 **왼쪽**에 있었다는 뜻이다.

## 5. 중요한 제약 — 메인 카메라 영상에서는 클릭이 성립하지 않는다

| 영상 소스 | 스트림 | 자세를 알 수 있나 | 클릭 |
|---|---|---|---|
| `simulator-99` (시뮬레이터 **메인** 카메라) | 13600 · 960×540 | **아니오** | ❌ |
| `simulator-2` (PTZ **카메라 1**) | 13601 · 1280×720 | 예 (`cam.get`) | ✅ |
| 실카메라 | rtsp | 해당 없음 | ❌ |

RPC 82개 어디에도 메인 뷰의 위치·방향·화각을 주는 것이 없다(`view.*` 자체가 없음). 그래서
**메인 영상 위에서는 화면이 "클릭이 되지 않습니다"라고 말하고 아무 것도 하지 않는다.**
대충 계산해서 엉뚱한 자리에 차를 놓는 것보다 낫다.

> 마스터께: 2·3번을 쓰시려면 영상 소스를 **「UE-시뮬2(cam1)」** 로 바꾸셔야 합니다.
> 메인 카메라에서도 쓰시려면 언리얼에 메인 뷰의 pos·rot·fov 를 주는 RPC(예: `view.get`)가
> 한 개 필요합니다.

### 설계 결정

- **계산은 서버가 한다.** `simCoords` 와 같은 이유다 — 기하가 두 벌이 되면 한쪽만 고쳐지고,
  그 실패는 오류로 뜨지 않는다(차가 조금 엇나간 자리에 놓일 뿐이다). 테스트가 화면 스크립트에
  `56.5` 나 `Math.tan/atan2` 가 나타나면 실패시킨다.
- **배치는 목록만 바꾼다.** 클릭으로 추가한 차량은 「추가」 버튼과 똑같이 이 화면의 목록에만
  들어간다. 시뮬레이터에 반영하려면 기존대로 「시뮬로 보내기」다.
- **고른 차가 목록에 없을 수 있다.** 클릭이 맞히는 것은 시뮬레이터의 현재 차량(`car.list`)이고
  목록은 파일에서 연 것일 수 있다. id 가 없으면 **그렇다고 말한다** — 비슷한 것을 골라 주지 않는다.
- **선택 반경은 영상 가로의 6%.** 그래야 "빈 자리를 찍었다"를 표현할 수 있고, 3번 배치가 그것을 쓴다.

## 7. 실제 동작 확인 (실서버 종단)

임시 검증 파일로 서버를 임시 포트에 띄우고 **실제 시뮬레이터**(192.168.0.125:13510)에 붙여
`POST /api/sim/pick` 을 호출했다. (확인 후 삭제 — 라이브 서버가 필요한 테스트는 커밋하지 않는다.)

영상에서 **눈으로 확인한** KIA SUV 보닛 위 픽셀 (720, 290) 을 클릭:

```json
{"camId":1,
 "pose":{"pos":{"x":-36.3,"y":-13.6,"z":13.5},"pan":47.1,"tilt":30.4,"zoom":2.4},
 "ground":{"x":-19.148684,"y":3.712470,"z":0},
 "car":{"id":"16-13.53.23","screen":{"x":717.75,"y":291.25},"distancePx":2.57}}
```

오인식 여지 검사:

| | 값 |
|---|---|
| 1순위(`16-13.53.23`) 거리 | **2.6 px** |
| 2순위(`63-16.48.26`) 거리 | **187.6 px** (72배) |
| 화면 안 차량 8대의 상호 **최소** 간격 | **129 px** (선택 반경 76px보다 넓다) |

간격이 반경보다 넓으므로 차량 원점이 반 대 길이만큼 어긋나 있어도 답이 뒤집히지 않는다.

**카메라 PTZ 는 모든 측정·확인 뒤 원래 값(pan 47.1 / tilt 30.4 / zoom 2.4)으로 되돌렸다.**

## 10. 남은 것

- **1번(방향 패드)** 은 지시가 없어 하지 않았다. `car.setPosition`·`setRotationY`·`groupMove`·
  `groupRotate` 는 살아 있고 지금 화면이 쓰지 않는다 — 원하시면 바로 붙일 수 있다.
- **메인 카메라 클릭**은 언리얼에 `view.get`(pos·rot·fov) 한 개가 필요하다.
- 화각 상수는 **카메라 1번에서 쟀다.** 카메라를 추가로 만들면 같은 값인지 한 번 확인하는 것이 좋다
  (같을 가능성이 높지만, 확인 안 한 것을 확인했다고 적지 않는다).
