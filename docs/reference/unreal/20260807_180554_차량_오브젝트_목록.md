## 3. 차종 분류 `ECarType`

열거형은 6종이다 — `Small`, `Medium`, `Large`, `Suv`, `Truck`, `Bongo`.

카탈로그 작성 당시 Type 은 **이름 기반으로 추정 입력**했다(원본 분류표 없음). 행별 Type 값은 이 문서에서 확인하지 못했다 — §5 참조.

## 4. `prefabId` 규약과 주의사항

**Unity 원본 규약**: `prefabId` 는 **1부터** 시작하고, 로드 시 `GetCarPrefab(prefabId - 1)` 로 0-based 배열을 참조한다(`unity/CarObject/CCarObjListUI.cs:142`). 저장할 때 0-based 인덱스를 그대로 쓰면 off-by-one 이 되므로 `+1` 해야 한다(같은 파일 336~346행에 경고 주석이 남아 있다).

**⚠ Park3D 의 Idx 는 이름순이다.** DT_CarCatalog 는 차량 23종을 이름순으로 1~23 매겼을 뿐, **Unity 원본 프리팹 배열 순서와 일치한다는 보장이 없다.** 카탈로그 작성 문서에도 미해결로 남아 있다.

> "여기서 `Idx` 는 이름순 순번이며 Unity JSON 의 `prefabId` 와 매핑이 다를 수 있음. 실제 prefabId↔차종 대응표(Unity 원본 카탈로그)가 확보되면 행 Idx/순서를 재정렬해야 함"
> — `Docs/20260624_110438_차량배치_3단계_구현_검증.md` §6

Unity 프리팹 배열은 인스펙터에 직렬화된 값이라 C# 소스에는 없다. **원본 Unity 프로젝트의 차량 리스트 순서를 확보하기 전에는 기존 `CarPos_*.json` 의 `prefabId` 가 Park3D 에서 다른 차종으로 뜰 수 있다.**

## 5. 사용 방법

**RPC**
```json
{"jsonrpc":"2.0","id":1,"method":"car.create",
 "params":{"pos":{"x":0,"y":0,"z":0},"prefabId":6,"presetId":1,"rotY":0}}
```
`prefabId` 생략 시 기본값이 쓰인다. 대량 배치는 `car.createLine`(+X 고정) 또는 `car.create` 반복 후 `random.recreateCars`.

**C++**
```cpp
UCarPlacementLibrary::PrefabNameFromId(Catalog, PrefabId);        // id → 이름
UCarPlacementLibrary::PrefabIdFromComboIndex(Catalog, Index, 1);  // 콤보 → id
UCarPlacementLibrary::NormalizeCarPrefabs(Catalog, Data);         // 범위 밖 id 보정
```

## 6. 검증 상태

- **23종 이름과 메시 경로**: `DT_CarCatalog.uasset` 의 행 데이터를 직접 파싱해 확인했다. 이름 목록과 `/Game/Cars/Car_no_plate/<이름>` 경로가 1:1로 일치한다.
- **치수·삼각형·머티리얼 슬롯**: `Docs/20260623_225559_차량메시_임포트_검증.md` 의 MCP 전수 감사 결과를 인용했다. 이 문서에서 재측정하지 않았다.
- **행별 `ECarType` 값**: **미확인.** uasset 바이너리에서 신뢰할 수 있게 추출하지 못했다. 필요하면 에디터에서 DT_CarCatalog 를 열거나, 런타임에 `CatalogFromTable` 결과를 덤프해야 한다.
- **`Idx` ↔ Unity `prefabId` 대응**: **미확정.** §4 의 주의사항이 그대로 유효하다.
