# 좌표 이동 속도 수정

## 개요

장비 프리셋 화면에서 `프리셋 이동`은 동작하지만, 동기화해 둔 좌표를 쓰는 `좌표 이동`이 동작하지 않는 문제를 수정했다.

저장 좌표는 `SettingMain/config/device-preset-registry.json`에 정상 존재했으며, UI와 REST 요청도 `mode: "coordinate"`를 명시적으로 보냈다. 실제 차이는 좌표 이동 전용 Hucoms direct adapter가 절대 이동 CGI에 속도 `0`을 보내던 점이었다.

## 변경 내용

### `SettingMain/src/clients/hyucomsDirectPresetClient.ts`

`HyucomsDirectPresetClient.goPtz(ptz)`가 `goptzfpos`를 호출할 때 다음 속도를 전송하도록 수정했다.

- `panspeed=50`
- `tiltspeed=50`
- `zoomspeed=50`

기존 값은 모두 `0`이었다. 일반 PTZ 제어 경로인 `SettingMain/src/clients/hucomsClient.ts`도 기본 속도 `50`을 사용하므로, 좌표 이동 전용 경로를 기존 동작과 일치시킨 것이다.

### `SettingMain/test/hyucomsDirectPresetClient.test.ts`

LF-only HTTP 헤더를 모사하는 소켓 테스트에서 `goPtz()`가 전송한 실제 요청 문자열을 검사한다. 저장 좌표 `pan=100`, `tilt=-200`, `zoom=300`과 함께 세 속도 값이 `50`으로 전송되는 것을 회귀 기준으로 고정했다.

## 외부 계약

변경하지 않은 계약:

- `POST /api/cameras/:cameraId/device-presets/:number/go`
- 요청 body: `{ "mode": "coordinate" }`
- 저장 좌표 shape: `{ pan, tilt, zoom }`
- 응답의 `mode`, `ptz`, `settled` shape
- 브라우저 호출: `SettingMain/web/api.js`의 `goDevicePreset(cameraId, number, mode)`

따라서 화면, 다른 REST 소비자, 레지스트리 JSON은 수정 없이 호환된다. 바뀐 것은 direct CGI 요청의 속도 값뿐이다.

## 영향도

| 대상 | 영향 |
|---|---|
| `SettingMain/src/api/server.ts` | coordinate 모드에서 기존처럼 `HyucomsDirectPresetClient.goPtz()`를 호출한다. 코드 변경 없음. |
| `SettingMain/web/control.js` / `web/api.js` | 좌표 이동 버튼 및 `{ mode: "coordinate" }` 호출 계약 유지. 코드 변경 없음. |
| `SettingMain/config/device-preset-registry.json` | 기존 학습 좌표를 그대로 사용한다. 스키마/값 변경 없음. |
| `SettingMain/src/clients/hucomsClient.ts` | 기본 속도 `50`이라는 일관성 근거만 제공하며 코드 변경 없음. |
| `AgentVLA`, `ParkAgent`, `SettingAgent` | 현재 Docker 작업공간에서는 해당 형제 프로젝트 경로를 찾지 못했고, API/설정 스키마가 바뀌지 않았으므로 수정한 코드는 없다. 실제 소비 여부는 해당 저장소 접근 시 추가 확인이 필요하다. |

## 미검증 항목

운영 중인 실제 Hucoms 카메라는 이동시키지 않았다. 실제 좌표 이동 확인은 안전한 시간/프리셋을 정한 뒤 화면에서 `좌표 이동`을 한 번 실행하고, 표시되는 PTZ가 저장값과 일치하는지 확인해야 한다.
