## 1. 무엇을 만들었나

TypeScript(Node ESM) 서비스 `SettingMain/` 과 웹 콘솔 2페이지(카메라 제어 · 옵션)를 만들었다.
런타임 npm 의존성은 **0개**다 — `node:http` 로 서버를 세우고, 영상 전사만 외부 `ffmpeg` 프로세스를 쓴다.

```
SettingManager/
├── Docs/                      한글 문서 (이 파일 포함)
└── SettingMain/
    ├── config/
    │   ├── config.json        ★ 카메라 기본정보 정본 (옵션 페이지가 갱신)
    │   ├── config.example.json
    │   ├── presets.json       프리셋 (첫 저장 시 생성)
    │   └── slots.json         실카메라 주차면 목록(수동 등록, 읽기 전용)
    ├── src/
    │   ├── index.ts           진입점
    │   ├── config/            설정 타입 · 정규화(순수) · 파일 저장
    │   ├── domain/            PTZ 좌표 · 프리셋 (외부 I/O 없음)
    │   ├── clients/           카메라 드라이버 (Hucoms CGI · backend-core REST)
    │   ├── stream/            RTSP→ffmpeg→MJPEG · JPEG 프레임 분리
    │   ├── store/             프리셋 · 주차면 영속
    │   └── api/               HTTP 라우터 · 정적 파일
    ├── test/                  7개 파일 · 102 테스트
    └── web/                   index.html · options.html · app.css · *.js
```

### 실행

```bash
cd SettingMain
npm install
npm start              # → http://127.0.0.1:13030/
```

## 3. 클래스·모듈 설명

### 3.1 `src/config/` — 설정

| 파일 | 역할 |
|---|---|
| `types.ts` | `AppConfig`·`CameraConfig`·`PublicCamera`·`SettingsPatch`. `config.json` 구조와 1:1 |
| `normalize.ts` | **순수** 정규화·병합. `normalizeConfig`(기본값 채움·URL 후행슬래시 제거), `toPublicCamera`(비밀번호 제거), `mergeSettings`(부분 갱신) |
| `configStore.ts` | 파일 I/O. 임시파일 → `rename` 원자적 저장. **JSON 파싱 실패 시 덮어쓰기를 거부** |

**비밀번호 규칙(설계상 중요):** GET 응답에는 `password` 필드 자체가 없고 `hasPassword: boolean` 만 나간다. 저장 시 **빈 비밀번호는 "변경 없음"** 으로 처리한다 — 화면이 비밀번호를 돌려받지 않으므로 빈 값을 그대로 쓰면 저장 한 번에 자격증명이 지워진다. 테스트로 못 박았다(`normalize.test.ts`, `server.test.ts`).

### 3.2 `src/domain/` — 순수 도메인

| 파일 | 역할 |
|---|---|
| `ptz.ts` | 계약 좌표(Hucoms 논리계). `wrapPan`(팬은 원이라 감는다) · `clampAxis`(틸트·줌은 자른다) · `limitedAxes`(잘린 축 보고) · `toView`(0.01°→도) · `nudge` |
| `preset.ts` | `addPreset`·`updatePreset`·`removePreset`·`listFor`. 카메라별 이름 유일성(409) |

**줌을 배율·화각으로 환산하지 않는 이유:** `zoompos` 는 **불투명 raw** 다(0~65535, 물리적 의미 없음). 환산하려면 기기별 실측 화각표(`zoomHfov`)가 필요하고 그것은 캘리브레이션의 산출물이다. 근거: `baro_calory/docs/cameras.md` §Hucoms. 이 규칙 때문에 화면은 줌을 raw 로만 보여준다.

> **형제 프로젝트와 다른 점(의도적):** SettingAgent 화면은 Pan `-141.55` / Zoom `23.88` 처럼 자체 도메인 값을 함께 보여준다. 그 환산의 근거(렌즈 캘리브 결과)를 이 저장소가 아직 갖고 있지 않으므로, SettingManager 는 **검증 가능한 것만** 보여준다 — 원시 raw 와 문서화된 0.01° 환산.

### 3.3 `src/clients/` — 카메라 드라이버

| 파일 | 역할 |
|---|---|
| `cameraDriver.ts` | 계약 표면 `CameraDriver` (`getPtz`·`goPtz`·`getSnapshot`·`listSlots`) + `CameraDriverError`(상태코드 보존) |
| `hucomsText.ts` | Hucoms `key = value` 파서. **본문 `Error:` 를 오류로 잡는다** — HTTP 200 으로 오므로 상태코드만 보면 조용히 틀린다 |
| `hucomsClient.ts` | `ptzf_status.cgi`(getptzfpos/goptzfpos) · `jpeg.cgi`. 쿼리 평문 인증. 오류 문구에서 비밀번호 마스킹 |
| `backendCoreClient.ts` | baro_calory `/api/ptz` · `/api/snapshot` · `/api/simulator/slots`. **501 을 확정 답으로 보존** |
| `driverFactory.ts` | 종류 분기가 있는 **유일한 지점**. 상위는 `CameraDriver` 만 본다 |

**드라이버 공통 방어 3가지**
1. **보내기 전에 자른다.** 기기는 범위 밖 요청에 성공이라 답하며 조용히 다른 데로 간다(`docs/cameras.md` 실측).
2. **없는 값을 0 으로 대체하지 않는다.** `panpos` 가 빠진 응답을 0 으로 읽으면 카메라가 원점으로 간다.
3. **스냅샷은 JPEG SOI 로 판정한다.** 인증 실패가 `200 text/plain` 으로 오기 때문이다.

### 3.4 `src/stream/` — 영상

| 파일 | 역할 |
|---|---|
| `jpegFrames.ts` | image2pipe 바이트열 → 완결 JPEG 프레임. 잘린 꼬리는 `rest` 로 이월 |
| `rtspUrl.ts` | 계정 주입(URL 에 적힌 것이 우선) · 로그용 마스킹 · ffmpeg 인자 조립 |
| `frameSource.ts` | RTSP 있으면 ffmpeg 전사, 없으면 **스냅샷 폴링**. 화면에서는 구분되지 않는다 |

ffmpeg 인자에 `-use_wallclock_as_timestamps 1` 과 `-fps_mode vfr` 을 **짝으로** 넣었다. 카메라가 RTP 타임스탬프를 실제 프레임률과 다르게 찍으면 기본 CFR 동기화가 빈 자리를 복제 프레임으로 채워 대역폭이 같은 그림에 쓰인다(근거: `baro_calory/docs/cameras.md` §RTSP 타임스탬프는 믿지 않습니다 — 실측 중복 50%→2%).

### 3.5 `src/api/` — HTTP

| 경로 | 메서드 | 설명 |
|---|---|---|
| `/api/health` | GET | 상태 |
| `/api/cameras` | GET | 카메라 목록(비밀번호 제외) |
| `/api/cameras/active` | POST | 활성 카메라 전환(설정 파일 반영) |
| `/api/ptz` | GET | 현재 PTZ (raw + 도) |
| `/api/ptz/absolute` | POST | 절대 이동. 응답에 `limited[]` |
| `/api/ptz/nudge` | POST | `{axis, delta}` 상대 이동 (delta 는 raw) |
| `/api/presets` | GET·POST | 목록 / 추가(`ptz` 생략 시 현재 자세) |
| `/api/presets/:id` | PUT·DELETE | 수정 / 삭제 |
| `/api/presets/:id/goto` | POST | 이동 |
| `/api/slots` | GET | 주차면 + `source: simulator\|local` |
| `/api/snapshot` | GET | JPEG 1장 |
| `/api/stream` | GET | multipart MJPEG |
| `/api/settings` | GET·PUT | 옵션 페이지 |

오류 매핑: `HttpError`→그 코드, `PresetError`→400/404/409, `CameraDriverError`→400/404/501/502, `ConfigError`→400, 나머지→500.

### 3.6 `web/` — 웹 클라이언트

| 파일 | 역할 |
|---|---|
| `api.js` | REST 계약 한 곳. 화면 코드는 `fetch` 를 직접 부르지 않는다 |
| `control.js` | 카메라 제어 페이지 로직 |
| `options.js` | 옵션 페이지 로직 |
| `app.css` | 다크 테마 (형제 프로젝트 콘솔과 같은 계열) |

**브라우저에는 계산이 없다.** step(°)→raw 변환 한 줄을 빼면 전부 서버가 낸 값을 그린다. 계산을 클라이언트에 두면 부르는 쪽마다 따로 두게 되고 그 순간 모델이 두 벌로 갈라진다(`baro_calory/docs/architecture.md` 의 원칙을 그대로 따랐다).

## 5. 영향도 분석 (CLAUDE.md 규칙 5)

### 5.1 이 저장소

전부 **신규 파일**이다. 기존 코드가 없었으므로 회귀 위험 없음. 기존에 있던 것 중 손댄 것은 없다(`CLAUDE.md`·`.claude/`·`README.md` 무변경).

새로 생기는 런타임 산출물: `SettingMain/config/presets.json`(첫 프리셋 저장 시), `SettingMain/node_modules/`(gitignore).

### 5.2 baro_calory

| 영향 | 내용 |
|---|---|
| 읽기 | `GET /api/ptz` · `/api/snapshot` · `/api/simulator/slots` 만 호출 |
| 쓰기 | `POST /api/ptz` — 시뮬 카메라를 **실제로 움직인다** |
| 코드 변경 | **없음.** 기존 REST 계약만 소비 |

설계서에 적었던 캘리브레이션·호밍 오케스트레이션은 **아직 붙이지 않았다**(다음 단계). 지금 붙은 것은 카메라 제어 평면뿐이다.

### 5.3 SettingAgent (형제 프로젝트)

| 영향 | 내용 |
|---|---|
| 코드 | 없음. 참조만 했다(Hucoms 와이어 계약·RTSP 전사 방식) |
| **런타임 충돌 가능** | 같은 실카메라를 동시에 조작하면 서로의 PTZ 를 흔든다. SettingManager 포트는 **13030**, SettingAgent 는 13020 이라 포트 충돌은 없다 |
| RTSP 세션 | 카메라에 따라 실데이터 세션이 하나뿐인 모델이 있다(IDIS 실측). 두 프로젝트가 동시에 스트림을 열면 한쪽이 프레임을 못 받을 수 있다 |

### 5.4 알려진 한계 (숨기지 않고 적는다)

1. **동시 조작 보호 없음.** 여러 브라우저 탭·다른 도구가 같은 카메라를 동시에 움직이면 서로 덮어쓴다. 설계서 §10 의 lease 는 아직 구현하지 않았다(캘리브·호밍을 붙일 때 함께 들어간다).
2. **정착(settle) 대기 없음.** 이동 직후 읽은 PTZ 가 이동 중간값일 수 있다. baro_calory 는 `waitForPtzSettle`(0.25초 폴링, 연속 2회 차이 ≤0.1°)로 해결하는데, 이번 범위에는 넣지 않았다. 화면에서 「현재 PTZ 불러오기」로 다시 읽으면 최종값이 나온다.
3. **인증 없음.** 서버는 무인증이고 기본 바인드가 `127.0.0.1` 이다. LAN 노출이 필요하면 리버스 프록시 뒤에 둔다.
4. **장비 내장 프리셋(1~255) 미지원.** 프리셋은 SettingManager 자체 저장소만 쓴다. 첨부 화면의 「장비 프리셋」 섹션에 해당하는 기능은 넣지 않았다 — 요구사항에 없었고, 두 프리셋 체계를 섞으면 어느 쪽이 정본인지 모호해진다.
