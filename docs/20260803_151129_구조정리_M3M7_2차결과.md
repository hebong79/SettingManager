## 1. 한 줄 요약

**같은 일을 하는 경로가 셋이었고 화면이 체크박스로 그중 하나를 골랐다.**
경로를 하나로 합치고, 구현 선택을 **질의 파라미터에서 설정으로** 옮겼다.
이제 `core.provider` 한 줄이 `local ↔ remote` 를 바꾸며 **화면 코드는 한 줄도 바뀌지 않는다.**

## 2. 단계별 실행 결과

### M3 — 계약 (`6c0c459`)

`src/core/coreProvider.ts` — **어떤 구현도 import 하지 않는 포트 정의.**
능력 6종(center · centerBox · discoveryPresets · discoveryPoints · calibration · plateHoming),
`CoreContext` · `JobPort` · `CoreUnsupportedError`(501) · `CoreBusyError`(409).

**계약의 정본은 타입이 아니라 적합성 스위트다**(`test/coreProviderConformance.ts`).
판정을 순수 함수로 분리하고, **스위트 자신이 판정하는지**를 `coreProviderContract.test.ts` 가 검증한다 —
13건 중 8건이 계약을 어긴 가짜 구현을 넣고 위반이 잡히는지 본다.
아무것도 잡아내지 못하는 스위트는 두 구현이 통과해도 아무것도 증명하지 못한다.

### M4 — RemoteCore (`6c0c459`)

| 분리 전 | 분리 후 |
|---|---|
| `BackendCoreClient` (driver 5 + 에이전트 6 메서드) | `devices/backendCore/backendCoreClient.ts` — **driver 표면만** |
| | `core/remote/remoteCoreProvider.ts` — 에이전트 표면 |
| | `devices/backendCore/backendCoreTransport.ts` — **전송 계층** |

**전송을 인터페이스로 뽑은 것이 Q2("MCP 를 통한 remote")에 대한 준비다.**
`RemoteCoreProvider` 는 전송을 직접 알지 않으므로, MCP 어댑터를 붙여도 그 파일은 바뀌지 않는다.

능력은 backend-core 의 `axes` 를 그대로 옮기고, **도달하지 못하면 지원한다고 지어내지 않는다.**
원격이 실어 보낸 추가 필드(`mode`·`deviceId`·`recent`)는 깎지 않고 통과시킨다.

## 3. 적합성 스위트가 잡아낸 실제 결함

스위트를 만든 값을 바로 했다.

| # | 결함 | 어디서 |
|---|---|---|
| 1 | 미지원 선언 능력을 그대로 원격에 흘려보내 **조용히 성공**하던 경로 | `RemoteCoreProvider` |
| 2 | `CoreUnsupportedError` 에 **엉뚱한 능력 이름**이 실림 | 테스트 가짜 구현 |

### 그 과정에서 계약도 고쳤다

처음 규칙은 "미지원이면 반드시 501" 이었다. 그런데 **읽기(status·list)는 못 하는 기기에서도
`idle` 을 읽는 것이 거짓말이 아니다** — backend-core 자신도 `status` 는 축 게이트 없이 답한다.

그래서 규칙을 정확히 좁혔다.

> 미지원 선언 능력의 **실행**은 조용히 성공하지 않는다. 오류의 종류는 구현의 사정이다
> (자체 구현 501 · 원격 422 · 도달 불가 502). 금지 대상은 오직 **조용한 성공**이다.

판정 대상도 읽기(`status`·`list`)에서 **행위**(`start`·`create`·`center`)로 바꿨다.

## 4. 검증

### 4.1 테스트 280/280

| 단계 | 결과 |
|---|---|
| M2 종료 시점 | 238 |
| M3·M4 | 267 (+29) |
| M5·M6·M7 | **280** (+13) |

신규: `coreProviderContract`(13) · `remoteCoreProvider`(17) · `localCoreProvider`(13).
**두 구현이 같은 적합성 스위트를 통과한다** — 교체 가능성의 증거다.

### 4.2 실기동 — 양방향 교체 확인

```
[기본 = local]
  GET /api/core/capabilities        → provider: local
                                       center=true, 나머지 5종 false + 사유
  GET /api/core/discovery/presets   → 501 "자체 코어는 아직 탐색 프리셋 조회을(를)
                                            지원하지 않습니다 — 옵션에서 …"

[설정 한 줄만 remote 로]
  PUT /api/settings {"core":{"provider":"remote"}}
  GET /api/core/capabilities        → provider: remote, discoveryPresets: true
  GET /api/core/discovery/presets   → 200 {"cameraId":"cam-real-001","presets":[],"busy":false}
                                       ← backend-core 실응답
```

**같은 URL, 같은 화면 코드, 다른 구현.**

| 항목 | 결과 |
|---|---|
| 옛 경로 5종(`/api/discovery/presets`·`/api/center`·`/api/center-box`·`/api/ptz/center`·`/api/independent-core/…`) | **전부 404** |
| 페이지 `/`·`/discovery`·`/options` | 200 |
| `grep -r "useBackendCore\|independent-core" web/ src/` | **0건** |
| `server.ts` 줄 수 | 74 |

**실카메라 PTZ 이동은 실행하지 않았다.** 운영 중인 물리 카메라라 별도 승인이 필요하다고 판단했고,
센터링 경로는 가짜 드라이버 기반 통합 테스트가 담보한다.

## 6. 영향도 분석

### 6.1 이 저장소

| 대상 | 영향 |
|---|---|
| **외부 API 계약** | 옛 경로 9종이 **사라졌다**(404). 소비자는 이 저장소의 `web/` 뿐임을 확인했다 |
| `config.json` | `core` 블록이 추가된다. 없으면 `{provider:'local', perCamera:{}}` 로 채워지므로 **기존 설정 파일이 그대로 열린다** |
| `web/**` | discovery·options·control 이 새 경로를 쓴다. **Ctrl+F5 필요**(정적 파일은 `no-store` 라 새로고침하면 최신) |
| 삭제된 소스 | `independentCameraCore/` 3파일, `api/routes/{independentCore,discovery}Routes.ts` |

### 6.2 외부

| 대상 | 영향 |
|---|---|
| `baro_calory` | **코드 변경 없음.** RemoteCore 가 소비하는 REST 계약 그대로 |
| 실카메라 · UE 시뮬 | 제어 방식 변경 없음(driver 계층 유지) |
| SettingAgent · `Sub/*` | 무관 |

### 6.3 동작이 바뀐 것 (숨기지 않고 적는다)

1. **기본 코어가 `local` 이라, 주차면 탐색·캘리브레이션·호밍이 기본 상태에서 501 이다.**
   쓰려면 옵션에서 「backend-core 경유」를 골라야 한다. 이전에는 체크박스를 켜면 됐다.
2. **`/api/ptz/center` 가 없어졌다.** 카메라 제어 화면의 영상 클릭 센터링은 `/api/core/center` 를 쓴다.
   동작은 같다(자체 코어 = 드라이버 직접 + 정착 대기).
3. **응답에 `provider` 필드가 실린다**(center 계열). 진단·표시용이며 화면은 분기하지 않는다.

## 7. 남은 것 — M8 이후

마스터 결정 Q1: **캘리브레이션·호밍을 LocalCore 에 이식하고 RemoteCore 와 공존시킨다.**

| 단계 | 내용 | 비고 |
|---|---|---|
| **M8** | `CalibrationComponent` | `@baro/profile` 솔버 + ZNCC 프레임 정합의 TypeScript 이식. 이번 작업 중 가장 큰 덩어리 |
| **M9** | `PlateHomingComponent` + `DetectorClient` | `Sub/lpd_api`·`Sub/vpd_api` 소스에서 계약 확인 — 추측 금지 |
| M10 | `DiscoveryStore` (자체 탐색 프리셋·점 저장소) | LocalCore 가 탐색을 지원하려면 필요 |

각 단계는 **적합성 스위트를 그대로 통과해야 하고**, 능력이 늘어나면 `capabilities()` 의 `ok` 가
false → true 로 바뀌는 것만으로 화면이 따라온다. 화면 코드는 더 이상 손대지 않는다.

### 아직 확인이 필요한 것

**Q2 의 "MCP 를 통한 remote"** — 전송 계층(`BackendCoreTransport`)은 준비해 두었지만,
그것이 **(a)** MCP 서버를 경유해 backend-core 를 부르는 것인지, **(b)** SettingManager 자신이
remote 코어를 MCP 도구로 노출하는 것인지에 따라 만들 어댑터가 다릅니다.
포트 계약은 어느 쪽이든 바뀌지 않으므로 M8 진행을 막지는 않습니다.
