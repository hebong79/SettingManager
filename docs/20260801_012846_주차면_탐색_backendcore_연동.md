# 주차면 탐색 페이지·BackendCore 연동

## 개요

SettingManager에 BackendCore 전용 주차면 탐색 화면을 추가했다. 탐색 프리셋과 주차면 점의 정본은 SettingManager의 기존 `presets`/`slots`가 아니라 BackendCore `discovery` 응답이다. 기존 제어 화면에서 `/discovery`로 이동하며, 활성 카메라가 BackendCore가 아니면 고급 기능을 숨기고 서버도 409로 거부한다.

## 변경 클래스·함수와 로직 의도

- `SettingMain/src/clients/backendCoreClient.ts`의 `BackendCoreClient`에 `discovery`, preset/point CRUD 및 goto, `calibration`, `center`, `plateHome`, `vlaTour`를 추가했다. 실제 BackendCore 경로와 body를 전달하고 409(busy), 422(capability), 501(unsupported)은 유지하며 기타 upstream 실패는 502로 변환한다.
- `SettingMain/src/api/server.ts`의 `handleDiscovery`는 `/api/discovery/*`, `/api/center`, `/api/center-box`, `/api/vla/tour`를 BackendCore에 프록시한다. `calibrationBody`, `centerBody`, `centerBoxBody`, `plateHomeBody`, `tourBody`가 입력을 검증하고 tour에는 `saveSpots:false`를 강제한다. 로컬 `/api/presets`, `/api/slots` 의미는 변경하지 않았다.
- `SettingMain/web/discovery.html`, `discovery.js`는 카메라 선택, discovery preset/point CRUD, goto, 개별 센터, calibration 및 번호판 home 상태 폴링(1.5초), VLA tour 테스트 UI를 제공한다. BackendCore discovery point는 `x/y/name`만 영속화하므로 `개별 센터+줌`은 UI에서 비활성화하고 미지원 사유를 표시한다. 서버의 `/api/center-box`도 BackendCore 활성 상태에서 501로 명시 거부해 비영속 box를 우회하지 않는다.
- `SettingMain/web/index.html`에 탐색 링크를 추가했다.
- `SettingMain/package.json`의 `start`를 nodemon 기반으로 조정하고 `nodemon` devDependency 및 lockfile을 반영했다.
- `.agents/skills/settingmanager-dev/SKILL.md`에 architect/developer/verification/qa/documenter 역할 모델과 책임(`gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`)을 등록했다.

## BackendCore 입출력·외부 계약

프록시가 사용하는 실제 endpoint는 `GET/POST/PUT/DELETE /api/discovery/presets[/:id]`, `POST .../:id/goto`, `GET/POST/PUT/DELETE .../:presetId/points[/:pointId]`, `POST /api/center`(`x,y`), `POST /api/center-box`(`startX,startY,endX,endY`), calibration start/stop/status, plate-home start/stop/status, `POST /api/vla/tour`이다. BackendCore 응답의 `cameraId`, `presets`, `points`, `busy` 등 shape은 SettingManager가 저장하거나 재명명하지 않고 전달한다. BackendCore 내부 active device와 SettingManager 카메라 목록은 자동 동기화하지 않으며, 응답 `cameraId`로 불일치를 드러낸다.

calibration, homing, center, preset goto, VLA tour는 카메라를 실제 이동시킬 수 있다. 따라서 UI는 409 busy와 422 capability를 노출하고 운영 승인 없이 이동 API를 실행하지 않았다. BackendCore point에 box가 저장되지 않는 계약 때문에 센터+줌은 성공 기능이 아니라 UI 비활성·서버 501 미지원 상태다.

## 영향도

- 직접 영향 파일은 `SettingMain/src/clients/backendCoreClient.ts`, `SettingMain/src/api/server.ts`, `SettingMain/web/discovery.html`, `SettingMain/web/discovery.js`, `SettingMain/web/index.html`, `SettingMain/package.json`, `SettingMain/package-lock.json`, 관련 `SettingMain/test/backendCoreClient.test.ts`, `SettingMain/test/server.test.ts`다.
- 공유 타입/설정: `BackendCoreJson`은 BackendCore JSON 전달용 `Record<string, unknown>`이며 카메라 kind는 기존 config의 `backend-core` 판별을 사용한다. URL, timeout, 오류 변환은 기존 `BackendCoreClient.send()` 규칙을 재사용한다. 새 discovery 데이터는 기존 로컬 `presets.json`/`slots.json` 설정 포맷에 저장하지 않는다.
- 의존성: `nodemon`이 `SettingMain` 시작 스크립트와 lockfile에 추가됐다.
- 형제 `baro_calory`는 코드 변경 없이 BackendCore endpoint/응답 계약의 소비자로만 영향받는다. 실제 정본 endpoint 근거는 `baro_calory/apps/backend-core/src/control-api.mjs`의 discovery, center, calibration, tour 구현이며, 해당 프로젝트의 카메라·시뮬레이터 코드는 수정하지 않았다.

## 테스트 및 QA 결과

후속 실행에서 `npm run typecheck`, `npm run test`, `npm run build`가 모두 통과했다. Vitest 결과는 **9 files, 171 tests 통과**이며 collection point POST, center+zoom 501 미지원, 409/422 전달, 비 BackendCore 409 차단, 정적 `/discovery` 계약을 포함한다. `git diff --check`도 공백 오류가 없었다.

QA는 기존 13030 리스너의 명령행을 확인해 SettingManager PID 23196만 종료한 뒤 `npm start`로 새 인스턴스를 기동했다. 새 프로세스에서 `GET /api/health` 200(`activeCameraId: simulator-1`), `GET /discovery` 200(주차면 탐색 HTML), 비지원 활성 카메라의 `GET /api/discovery/presets` 409를 실제 확인했고 종료 시 해당 npm/nodemon/server 계보만 정리했다.

후속 실제 `npm start` 검증에서 기존 13030 리스너가 없음을 확인한 후 새 인스턴스의 `/api/health`, `/discovery`, `/discovery.js` 200과 hucoms 활성 상태의 discovery 409를 확인했다. 현재 실제 카메라 목록에는 `backend-core` kind가 없어 BackendCore safe GET의 실제 응답 및 discovery schema는 미검증이다. calibration, center, plate-home, goto, VLA tour 등 이동 API도 카메라 이동 위험과 운영 승인 부재로 실행하지 않았다. 이 미검증·미실행 항목을 성공으로 간주하지 않는다.

## 후속 개정 (2026-08-01)

독립 검증에서 discovery point가 box를 저장하지 않는 BackendCore 실제 계약을 확인했다. 이에 따라 선택 point가 있어도 추가는 항상 collection `POST /api/discovery/presets/:presetId/points`를 사용하도록 수정했고, box 입력·활성 센터+줌을 제거했다. `centerBox` 버튼은 `개별 센터+줌 (미지원)`으로 disabled이며 `/api/center-box`는 501과 명시 사유를 반환한다. VLA tour는 box에 의존하지 않고 `{zoomIn:false, saveSpots:false}`를 보낸다.
