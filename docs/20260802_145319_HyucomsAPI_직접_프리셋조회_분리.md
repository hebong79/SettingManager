# HucomsAPI 직접 프리셋 capability 조회 분리

작성 시각: 2026-08-02 14:53:19 (Asia/Seoul)

## 개요

SettingManager에 Hucoms 장비의 PTZ preset 지원 여부를 읽기 전용으로 조회하는 전용 경계를 추가했다. 기존 RTSP/PTZ 제어 경로는 성공했지만 동일 장비의 capability `fetch`는 HTTP 502가 발생했다. `Sub/HyucomsAPI`의 Python `get_capabilities_ptz()`는 실제 장비에서 원문 `PresetSupported = Yes`를 성공적으로 반환했으며, 기본 Node HTTP 파서는 `Missing expected CR after header value`로 실패했다. 따라서 비표준 응답 수용을 `HyucomsDirectPresetClient`의 capability GET 한 곳으로만 격리했다.

## 변경 클래스·함수와 로직 의도

- `SettingMain/src/clients/hyucomsDirectPresetClient.ts`의 `HyucomsDirectPresetClient.getCapability/getText`: 고정 `/cgi-bin/control/capabilityptz.cgi?action=getPTZ`를 `node:http`/`node:https`로 조회하고 `insecureHTTPParser: true`를 이 요청에만 적용한다. 2xx, timeout, 64KiB body 상한, `Error:` 파싱 및 비밀번호 redaction을 보장한다.
- 같은 파일의 `capabilityUrl`: http(s)만 허용하고 embedded credential, query, fragment를 거부한 뒤 `id`, `passwd`, `action=getPTZ`를 `URLSearchParams`로 구성한다.
- `SettingMain/src/clients/cameraDriver.ts`의 `DevicePresetCapability/DevicePresetSlot`: `supported`, nullable `advertisedMaxPresetNumber`, 안전 상한, `listing/naming='unsupported'`, `registration='unknown'`, `name=null` 계약을 정의한다.
- `SettingMain/src/api/server.ts`의 `GET /api/device-preset-capability`: `configStore.get()`→`findCamera()` 후 Hucoms일 때만 직접 client를 생성한다. 비-Hucoms는 501이며 `driverFor`, `createDriver`, `BackendCoreClient`를 거치지 않는다.
- `SettingMain/web/api.js`, `control.js`, `index.html`, `app.css`: 초기 진입·카메라 변경 시 direct endpoint를 조회해 compact scroll 목록을 표시한다. `Yes`는 `#1..#255`, 숫자 `1..255`는 `#1..#N`, `No`는 빈 목록이며 등록 여부·이름을 추측하지 않는다.

## 입력·출력 및 외부 계약

`PresetSupported=No`는 `supported=false`, 슬롯 0개다. `Yes`는 장비가 최대값을 광고하지 않으므로 `advertisedMaxPresetNumber=null`, 안전 후보 255개를 반환한다. 십진 `1..255`는 해당 범위 후보를 반환한다. 누락·0·256 초과·기타 문자열은 502 계약 오류다. 후보 슬롯은 등록 목록이나 이름 목록이 아니다.

`Sub/HyucomsAPI/README.md`는 PTZ capability와 `set/go/clear_preset`을 공개 기능으로 열거하고, `HUCOMS_API_DESIGN.md` 및 `hyucoms_api/client.py`는 capability CGI와 preset 제어 번호 범위 `1..255`를 근거로 한다. 이번 변경은 `setpreset`, `gopreset`, `clearpreset` route·adapter·UI·명령을 추가하거나 실행하지 않았다.

## 영향도 및 경계

- 직접 변경 경로: `SettingMain/src/clients/*`, `src/api/server.ts`, `web/{api.js,control.js,index.html,app.css}`, 관련 Vitest.
- 로컬 `/api/presets`·`PresetStore`와 BackendCore `/api/discovery/**`는 capability 정본이나 fallback으로 사용하지 않는다. 직접 adapter는 BackendCore import·생성·호출 및 discovery URL 참조가 없다.
- `Sub/HyucomsAPI`는 계약 근거로만 읽었고 수정하지 않았다. `AgentVLA/ParkAgent/SettingAgent` 및 BackendCore에도 변경·호출이 없다. 새 endpoint를 소비하지 않는 형제 시스템에는 동작 영향이 없다.
- 인증 정보는 URL/오류에서 redaction하며 timeout과 body cap으로 자원·정보 노출을 제한한다. redirect는 추적하지 않는다.

## 테스트 및 실환경 결과

QA 최종 결과는 `npm run typecheck` 통과, `npm run build` 통과, `npm run test` **199 passed / 0 failed (10 files)**, `git diff --check` 통과다. 첫 실행의 12개 실패는 URL encoding 및 오류 상태 매핑 불일치였고 수정 후 targeted 76개와 전체 회귀를 통과했다. 최초 QA 결함은 non-Hucoms에서도 `driverFor()`가 BackendCore client를 만들던 것이며, config 조회·camera 종류 확인 후 direct client를 만들도록 수정했다.

실행 중인 서버에 `GET /api/device-preset-capability?cameraId=real-camera-2`만 요청해 HTTP 200, `supported=true`, `advertisedMaxPresetNumber=null`, `usableMaxPresetNumber=255`, 첫/마지막 슬롯 1/255를 확인했다. RTSP/PTZ 성공 사실과 별개로 기존 Node `fetch` capability 경로는 502였고, 표준 `node:http`는 CR parse error였으며, Python 직접 호출과 격리 adapter는 동일한 `Yes` 원문을 성공 처리했다. PTZ 이동 및 set/goto/clear 명령은 실행하지 않았다. 브라우저 실렌더링은 in-app browser 부재로 미검증이며, 정적 UI 계약 테스트와 정적 파일 GET만 확인했다.
