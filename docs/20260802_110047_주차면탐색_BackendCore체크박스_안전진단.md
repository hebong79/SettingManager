# 주차면 탐색 BackendCore 체크박스 전환 및 PowerShell 안전 진단

## 변경 목적

BackendCore 사용 여부를 카메라별 Options의 타입으로 지정하지 않고, **주차면 탐색 화면에서 사용자가 직접 체크박스로 선택**하도록 변경했습니다.

## 사용 방법

1. Options (`/options`)
   - 상단 **BackendCore URL**에 실제 BackendCore API base URL을 저장합니다.
   - 카메라 추가/편집에는 backend-core 타입 선택이 없습니다. 카메라는 Hucoms CGI/영상 URL만 관리합니다.
2. 주차면 탐색 (`/discovery`)
   - 스트림으로 볼 카메라를 선택하고 필요하면 **활성으로 선택**합니다.
   - **BackendCore 사용 (주차면 탐색·센터링·자동 작업)**을 체크합니다.
   - 체크된 경우에만 탐색 프리셋, 점, 자동 작업 및 영상 클릭 센터링을 실행합니다.
3. 체크하지 않으면 고급 버튼이 비활성이고 서버도 `409`으로 거부합니다.

## API 동작

체크박스를 켠 UI는 discovery/center 요청에 `useBackendCore=1`을 붙입니다.

```text
주차면 탐색 UI
  → /api/discovery/*?useBackendCore=1 또는 /api/center?useBackendCore=1
  → SettingMain global BackendCore URL
  → BackendCore API
```

이 경로는 selected camera의 legacy `kind` 또는 camera `controlUrl`을 BackendCore URL로 사용하지 않습니다. 이는 카메라 CGI URL로 `/api/center`를 보내 Apache HTML 400을 받는 혼동을 줄입니다.

## PowerShell 안전 진단

생성 파일:

```text
scripts/test-settingmanager-safe.ps1
```

마스터 Windows PowerShell에서 SettingManager 루트로 이동한 뒤 다음을 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test-settingmanager-safe.ps1
```

다른 포트면 다음처럼 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test-settingmanager-safe.ps1 -BaseUrl http://localhost:13030
```

이 스크립트는 다음 GET만 호출하며 PTZ 이동 요청을 절대 보내지 않습니다.

- `/api/health`
- `/api/cameras`

- 전체 Vitest 16개 파일, 237/237 통과
- `npm run typecheck` 통과
- `npm run build` 통과

## 미검증

이 에이전트는 Docker/Linux에서 실행되어 Windows PowerShell 또는 마스터의 `localhost:13030`에 직접 접근할 수 없습니다. 따라서 운영 PowerShell 실행과 실제 PTZ 이동은 수행하지 않았습니다.
