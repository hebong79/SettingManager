실측 응답 예:

```jsonc
cam.list   → {"cameras":[{"camId":1,"name":"Camera-1",
                          "pos":{"x":-36.3,"y":-13.6,"z":13.5},
                          "pan":47.1,"tilt":30.4,"zoom":2.4,"streamPort":13601}]}
cam.getPTZ → {"pan":47.1,"tilt":30.4,"zoom":2.4}
car.list   → {"cars":[{"carNameId":"0-13.50.46","presetId":1,"faceSlot":2,
                       "visible":true,"pos":{...},"rotY":180,"prefabId":1}, …]}
preset.list→ []                        (지금 프리셋이 하나도 없다)
map.get    → {"sizeX":160,"sizeZ":160}
measure.cameraHeight {camId:1} → {"height":13.5}
cam.streamStatus → {"channels":[{"camId":1,"port":13601,"clients":0,
                                 "holdsSlot":false,"pinned":false,"fps":0,"serving":true}],
                    "slots":1,"hardMaxSlots":2,"totalFps":5,"channelFps":5,
                    "basePort":13600,"maxCameras":50}
```

**설계에 직접 영향을 주는 실측 사실 4가지**

1. **좌표계가 Z-up 이다.** `pos.z = 13.5` 가 높이이고 `measure.cameraHeight` 도 13.5 를 준다.
   Unity 계약(Y-up)과 축이 다르다 — 화면 라벨을 Unity 기준으로 적으면 사람이 반대로 입력한다.
2. **PTZ 단위가 도·배율 실수다.** `pan 47.1` 은 47.1°, `zoom 2.4` 는 2.4배.
   `park3dRpcClient.ts` 가 ×100 정수 raw 로 바꾸는 건 **카메라 드라이버 계층의 사정**이다 —
   시뮬레이터 툴은 격리 모듈이므로 **변환 없이 도·배율 그대로 쓴다**(§4.2).
3. **동시 스트림 슬롯이 `slots:1`, `hardMaxSlots:2` 다.** 카메라 스트림을 한 번에 1개만 뜬다.
   주차면 페이지가 카메라 영상을 보고 있는 동안 시뮬툴이 또 뜨면 **서로 슬롯을 뺏는다**.
   `pinStream`·`setStreamSlots`·`streamStatus` 가 그 관리 수단이다 — §4.3 이 이걸 쓴다.
4. **오류 형태가 두 가지로 정확히 갈린다.**
   - 미등록 method → `-32601 "미등록 method: light.get"`
   - 도메인 위반 → `-32000 "타겟점 미설정 — measure.setTargetPoint 를 먼저 호출하세요."`

   둘 다 **HTTP 200 + error 봉투**다. 클라이언트가 상태코드를 먼저 보면 사유가 통째로 사라진다
   (`park3dRpcClient.ts:145-149` 가 이미 그렇게 막아 뒀다 — 같은 규약을 쓴다).

## 3. Part A — 주차면 페이지

### 3.1 페이지·탭 구조

```
/parking                                     ← 신규
┌───────────────────────────────────────────┐
│ 대상 카메라 [카메라 ▼] [활성으로 선택]        │  ← 탭 밖 (3탭 공용)
│             코어: bridge · 능력 뱃지          │
├───────────────────────────────────────────┤
│ [주차면 탐색] [캘리브레이션] [차량 3D]         │  ← .tabs (options.html 패턴)
├──────────────────────┬────────────────────┤
│  (탭 패널)            │  카메라 뷰 (공용)     │
└──────────────────────┴────────────────────┘
```

**카메라 선택·능력 조회·영상 뷰포트를 탭 밖 공용으로 뺀다.** 지금 세 화면이 각자
`<img id="stream">` 과 시작/정지 버튼을 갖고 있는데 탭으로 합치면 1벌이면 된다.
탭을 바꿔도 스트림은 유지하고, 오버레이(센터 십자 / 클릭 마커 / 차량 3D 캔버스)만 갈아 낀다.

`GET /api/core/capabilities?cameraId=` 한 번으로 세 탭의 버튼 활성/비활성이 동시에 정해진다.

**라우팅은 서버 변경이 없다** — `server.ts:81` 이 확장자 없는 경로를 `.html` 로 매핑한다.
`web/parking.html` + `web/parking.js` 를 두면 `/parking` 이 뜬다.

**상단 nav**: `카메라 제어 | 주차면 | 시뮬레이터 툴 | 옵션 | DB 테이블`
`/discovery`·`/calibration`·`/vehiclebox` 는 **지우지 않는다** — 북마크와 테스트가 통째로 깨진다.

### 3.2 탭 ① 주차면 탐색 — 캘리브레이션 제거

```
┌ 탐색 프리셋 ────────────────┐
│ [프리셋 ▼] [이동]            │
│ [이름__] [추가][수정][삭제]   │
├ 주차면 점 ─────────────────┤
│ [점 ▼] x[__] y[__]          │
│ [추가][수정][삭제][개별 센터] │
├ 번호판 호밍 ───────────────┤   ← 캘리브레이션 카드 자리를 대체
│ [시작][정지]  상태 idle       │
│ 진행 3/12 · 현재 pt-7 · 118px │
│ 결과표: 점 | 상태 | closeup   │
│ 실패 점 클릭 → 스텝 프레임 재생│
└───────────────────────────┘
```

호밍이 캘리브레이션보다 화면을 더 요구한다 — 캘리브는 "돌려놓고 기다리는" 일이지만
호밍은 **점마다 성패가 갈리고 실패 사유가 다르다.**

**`discovery.js` 변경**

| 삭제 | `calibrationMode`·`calibrationStart`·`calibrationStop`·`calibrationStatus` 및 141행의 바인딩 |
| 축소 | `poll()` 이 `/api/core/calibration/status` 를 더 읽지 않는다 |
| 유지 | 센터링(`/api/core/center`) · 탐색 프리셋·점 · 스트림 클릭 센터링 |
| 추가 | 호밍 상태 폴링 — `results[]`·`current`·`targetPx`·`cameraStranded` |

### 3.3 탭 ② 캘리브레이션 / 3.4 탭 ③ 차량 3D

`calibration.*`·`vehiclebox.*` 를 **로직 변경 없이 패널로 옮긴다.** 대상 카메라 카드와
영상 카드가 공용으로 빠지므로 각 탭에는 고유 제어만 남는다.

```

```

### 4.3 main 카메라 스트리밍 (지시 6) — **신설 필요**

실측: 스트림은 `13600 + camId` 의 **PTZ 카메라 전용**이고, `view.get` 은 `-32601` 이다.
main(자유 시점) 뷰 스트림이 없다.

**언리얼 신설 `view.*` (4)**

| method | params | result |
|---|---|---|
| `view.get` | — | `{pos{x,y,z}, rot{pitch,yaw}, fov, streamPort}` |
| `view.set` | `{pos?, rot?, fov?}` | 갱신된 상태 |
| `view.pick` | `{x, y}` 뷰 픽셀 | `{hit, world{x,y,z}, actorId?}` — 바닥 라인트레이스 |
| `view.lookAt` | `{world{x,y,z}, distance?}` | 갱신된 상태 |

+ main 뷰 MJPEG 채널 1개 (`view.get.streamPort`, 예 13599 또는 13650).
기존 `cam.*` 스트림 구조를 그대로 복제하되 소스가 플레이어 뷰포트다.

**클릭 피킹은 `view.pick` 이 한다 — 웹이 기하를 재현하지 않는다.** 언리얼이
`DeprojectScreenToWorld` + 라인트레이스로 정답을 안다. 웹이 흉내 내면 반드시 갈린다.

#### 스트림 슬롯 충돌 (실측 `slots:1, hardMaxSlots:2`)

주차면 페이지가 카메라 영상을 보는 동안 시뮬툴 main 뷰가 뜨면 슬롯을 다툰다. 대응:

1. main 뷰 스트림을 **슬롯 밖 채널**로 만든다 (플레이어 뷰포트는 SceneCapture 를 새로 켜지 않는다) — 우선 방침
2. 그게 안 되면 시뮬툴 연결 시 `cam.setStreamSlots {slots:2}` 로 올리고, 화면 상단에
   `streamStatus` 를 실시간 표시해 **사람이 다툼을 볼 수 있게** 한다
3. 어느 쪽이든 **조용히 남의 스트림을 끊지 않는다**

`src/sim/simCatalog.ts` 에 허용 목록을 두고, 테스트가 살아 있는 서버의 `system.catalog`
응답과 대조해 **어긋나면 실패**한다. MCP 서버가 `routeCatalog.ts` 로 라우트 드리프트를
잡는 것과 같은 방식이다. **시뮬레이터가 안 떠 있으면 건너뛴다** — 연결 없음은 실패가 아니다.

## 8. 미결 사항과 리스크

### 미결 — 마스터 확인 필요

| # | 내용 |
|---|---|
| **Q1** | `preset.list` 가 **빈 배열**이다(실측). 프리셋 메이커를 검증하려면 데이터가 있는 레벨이 필요하다. 지금 레벨에서 만들어 가며 검증하나, 아니면 저장된 프리셋 파일이 있나? |
| **Q2** | **호밍 검증 환경.** "판이 읽힌다" 기준을 만족하려면 번호판이 보이는 카메라 + LPD·VPD 사이드카가 필요하다. 실측 `config.json` 은 `detectors.*.baseUrl` 이 **전부 비어 있다**. 어느 환경으로 검증하나? |
| **Q3** | 카메라 컨트롤의 **Min/Max** 가 시뮬레이터에 저장되는 제약인가, 화면 슬라이더 범위일 뿐인가? 후자면 `cam.setLimits` 는 불필요하고 웹 로컬 상태로 끝난다 |
| **Q4** | 프리셋의 `Camera idx` 와 SettingManager `camera_info.cam_id` 가 같은 축인가. `schema.ts:32` 는 "우연히 같을 뿐 다른 축"이라고 못 박아 뒀다 |
| **Q5** | `preset.get` 응답에 파생값(각도·step폭·전체X폭·세로폭)이 실려 오는가? (`preset.list` 가 비어 있어 확인 못 함) 없으면 `derived` 필드 추가를 요청한다 |
| **Q6** | 차량 **프리팹 이름 목록**(기아_K5 등)과 **차량 타입**(소형차 등)을 주는 method 가 있는가? `car.get` 은 `prefabId` 숫자만 준다 |

### 리스크

| 리스크 | 대응 |
|---|---|
| **VPD 세그멘테이션 계약이 실제와 다를 수 있다** — `vpdClient.ts` 가 "필요해지면 다시 보라"고 남겨 뒀다 | A3 을 **소스 재확인부터** 시작한다. 틀리면 호밍 일정 전체가 밀리므로 가장 먼저 확인 |
| **스트림 슬롯 1개** — 주차면 페이지와 시뮬툴이 다툰다 | §4.3 — main 뷰를 슬롯 밖으로 두거나, `streamStatus` 를 화면에 실시간 표시해 사람이 보게 한다. **조용히 남의 스트림을 끊지 않는다** |
| **Z-up ↔ Y-up 혼동.** 스크린샷 라벨("Camera Z 축 이동")이 언리얼 축과 반대다 | 화면 라벨을 `X축(좌우)/Y축(앞뒤)/높이(Z)` 로 다시 적고 툴팁에 근거를 남긴다 |
| **단위 이중 변환.** 드라이버는 ×100 raw, 시뮬툴은 도·배율 | 격리 경계가 이걸 막는다. 테스트가 `src/sim/**` 의 `devices/` import 를 금지한다 |
| `discovery.js` 141행이 한 줄에 4개 바인딩 | A2 에서 **그 줄만** 여러 줄로 풀고 다른 것은 손대지 않는다 |
| 탭 이식 중 기존 테스트가 대량으로 깨진다 | A1 을 **로직 변경 없는 순수 이동**으로 못 박았다 (구조정리 M1 의 교훈) |
| 시뮬레이터가 꺼져 있으면 시뮬툴 테스트가 못 돈다 | 카탈로그 대조 테스트는 **연결 없으면 skip**. 나머지는 가짜 fetch 로 돈다 |
