# 탐색 UI 가시성 및 BackendCore 연결 안내

## 개요

2026-08-01 기준 Discovery 화면은 카메라 종류와 관계없이 탐색 프리셋, 주차면 점, 자동 작업(캘리브레이션·번호판 호밍·VLA 투어), 센터링 영역을 렌더링한다. Hucoms가 활성인 경우에도 카드를 숨기지 않고 네이티브 `disabled` 상태와 안내 문구를 표시한다. 실행 조건은 **선택한 카메라가 현재 활성 카메라이며 `kind === 'backend-core'`인 경우**로 제한된다.

## 변경 클래스·함수와 로직 의도

- `SettingMain/web/discovery.js`
  - `refreshCameras()`가 `/api/cameras`의 `activeCameraId`를 보존한다.
  - `setCapability()`가 선택 ID·활성 ID·`backend-core` 종류의 이중 게이트를 계산한다. Hucoms 또는 선택/활성 불일치에서는 `#advanced` 내부 모든 `input/select/button`을 네이티브 disabled로 바꾸고 poller를 해제하며 preset/status 선조회를 하지 않는다.
  - 활성 BackendCore에서만 `loadPresets()`, `poll()`, 1.5초 poller를 시작한다.
  - BackendCore 후보를 고르기만 한 경우 “활성으로 선택” 절차를, Hucoms 활성인 경우 `/options`에서 기기 추가·타입 변경·제어 URL(또는 시뮬레이터 BackendCore URL) 설정 후 활성 선택 절차를 안내한다.
  - `centerBox`는 어떤 상태에서도 disabled이며 box 좌표 미지원 사유를 title로 제공한다.
- `SettingMain/web/discovery.html`
  - `#advanced`, 탐색 프리셋·주차면 점·자동 작업·캘리브레이션·번호판 호밍·VLA 투어를 정적 HTML에 항상 포함한다.
  - `#cameraNote`, capability 상태 및 `/options` 링크를 제공한다.
- `SettingMain/web/app.css`
  - `.capability-note` 및 `.capability-note.ready`로 경고/정상 상태를 텍스트와 색으로 구분하되 카드 전체를 숨기거나 흐리지 않는다.
- `SettingMain/src/api/server.ts`의 `handleDiscovery()`
  - 서버는 계속 활성 카메라만 사용한다. 비-BackendCore 활성 카메라에는 409를 반환해 UI 우회 호출을 방어한다.
  - `/api/center-box`는 discovery point에 box 좌표 정본이 없으므로 501(개별 센터+줌 미지원)을 유지한다.
- `SettingMain/src/clients/backendCoreClient.ts`의 `BackendCoreClient`
  - discovery·calibration·plate-home·center·VLA tour 프록시와 외부 409/422/501 오류 보존을 담당한다.

## 입출력 및 외부 계약

- `GET /api/cameras` 응답은 `{ activeCameraId, cameras }`이며 공개 카메라 DTO(`id`, `label`, `kind`, `controlUrl`, `username`, `streamUrl`, `timeoutMs`, `hasPassword`)만 노출한다. 저장 `password`와 비밀번호 문자열은 응답에 포함하지 않는다.
- Discovery API는 요청별 cameraId를 받지 않고 설정의 활성 카메라를 사용한다. 따라서 UI의 선택+활성+종류 게이트와 서버의 409 방어가 함께 필요하다.
- BackendCore가 활성인 경우 `/api/discovery/*`, `/api/center`, `/api/vla/tour`가 BackendCore REST로 전달된다. 외부 409(충돌), 422(capability 오류), 501(미지원)는 상위 오류 코드로 보존된다.
- `centerBox`/개별 센터+줌은 영구 미지원이다. 점의 x/y/name만 영속화하며 box 좌표를 새 정본으로 만들지 않는다.
- 연결 설정은 기존 `SettingMain/web/options.html`·`options.js`의 기기 추가, `backend-core` 타입, 제어 URL, 적용 및 연결 테스트 계약을 재사용한다. 설정 포맷과 `SettingMain/config/config.json`은 변경하지 않았다.

## 영향도

- 직접 영향: `SettingMain/web/discovery.html`, `SettingMain/web/discovery.js`, `SettingMain/web/app.css`, `SettingMain/test/server.test.ts`.
- 연계 영향: `SettingMain/src/api/server.ts`, `SettingMain/src/clients/backendCoreClient.ts`, `SettingMain/src/clients/driverFactory.ts`의 BackendCore 라우팅·오류 계약이 UI 게이트의 서버 측 안전 경계를 제공한다.
- 기존 기능 영향: Hucoms의 일반 PTZ/영상/옵션 기능은 유지된다. Discovery 고급 카드는 보이지만 Hucoms 활성 상태에서 조작·폴링·고급 API 호출이 차단된다. 활성 BackendCore에서는 기존 discovery CRUD와 자동 작업이 다시 활성화된다.
- 공개 DTO·설정·의존성: `SettingMain/src/config/types.ts`, `normalize.ts`, `package.json`, `tsconfig.json`, `vitest.config.ts`의 계약과 의존성은 변경하지 않았다.
- 형제 `AgentVLA/ParkAgent/SettingAgent`에는 코드·설정 변경이 없고, 해당 프로젝트의 별도 계약을 추측해 확정하지 않았다. VLA 투어는 기존 `/api/vla/tour` 프록시 경계만 사용한다.

## 검증 결과

`SettingMain/`에서 다음이 실제 성공했다.

- `npm run typecheck` — 성공
- `npm run test` — 성공, 9개 파일·177개 테스트 통과
- `npm run build` — 성공
- 실행 서버 HTTP: `/discovery` 200, `/api/cameras` 200(활성 `simulator-1`, 세 카메라 모두 Hucoms), `/api/discovery/presets` 409, `/options` 200.
- 정적/소스 회귀에서 고급 카드·`hidden` 부재·`href="/options"`·이중 게이트·Hucoms poller 중단·전체 native disabled·`centerBox` 영구 disabled·공개 DTO 비밀번호 비노출을 확인했다.

인앱 브라우저가 `Browser is not available: iab`로 제공되지 않아 실제 렌더링·탭 순서·개발자 도구 네트워크 관찰은 수행하지 않았다. 운영 설정에 BackendCore 카메라가 없어 BackendCore 활성 화면, preset/status 폴링 및 지원 버튼 활성화도 미검증이다. 실제 카메라 이동과 calibration/center/home/tour 시작 요청은 실행하지 않았다. 이 미검증 항목은 성공으로 간주하지 않는다.

## 비범위

BackendCore 내부 active device 자동 동기화, 새 capability probe/DTO 필드, options 마법사·자동 URL 탐색, 운영 config 변경, 인증·lease·다중 탭 조정, `centerBox` 활성화, 알고리즘 및 형제 SettingAgent 코드 변경은 포함하지 않는다.
