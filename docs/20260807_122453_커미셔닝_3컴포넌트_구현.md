## 2. 만든 것

### 2.1 공용 기반 — `src/profiles/` (컴포넌트가 아니다)

A·B **둘 다** 필요로 하므로 기반이다. 정본은 상류 `docs/calibration.md` §프로파일 생명주기 정책.

| 파일 | 역할 |
|---|---|
| `profileTypes.ts` | 발행본 문서 형식. **상류 실물(`cam-real-001/rev-0001.camprof.json`)에서 읽어 온 모양**이고 지어내지 않았다 |
| `profileStore.ts` | `publish`(max(rev)+1 · tmp+rename · `.sha256`) · `read(@N)` · `apply` · `retire` |
| `publishGate.ts` | `fitRmsMedianPx ≤ 20` · 쓸 수 있는 표본 ≥ 50% · `force` 시 사유 기록 |
| `profileDrift.ts` | 발행본(분모) 대비 런타임 이탈 |
| `dbIntrinsicsSink.ts` | 런타임 적용본 쓰기 — **이 저장소에서는 `camera_info.intrinsics`** |

**못 박은 규칙과 그것을 강제하는 자리**

| 규칙 | 강제 |
|---|---|
| **적용이 먼저, 발행이 나중** | `publish()` 가 `sink.apply()` 뒤에만 파일을 쓴다. 테스트: *"적용에 실패하면 문서도 남지 않는다"* |
| 리비전은 불변 | `max(rev)+1` 로만 쓰고 기존 파일을 열지 않는다. **`PUT` 라우트를 두지 않았다** |
| `@N` 고정 조회는 영원히 유효 | 폐기 없음. 삭제는 **퇴역**(`.trash/`)이고 런타임 적용본은 안 건드린다 |
| 판정은 최댓값이 아니라 **중앙값** | `publishGate.ts`. 중앙값이 없는 옛 측정본은 최댓값으로 판정하되 **그 사실이 문구에 드러난다** |
| 우회는 막지 않되 기록 | `force:true` → `quality.forced` 배열. **화면에도 「그래도 발행」이 있다**(API 에만 두면 우회로가 아니다) |

### 2.2 컴포넌트 A — `src/calibration/`

| 파일 | 역할 |
|---|---|
| `jpegSize.ts` | SOF 마커 직독 → `{width,height}` (~90줄, 순수) |
| `frameDecode.ts` | **ffmpeg** 로 JPEG → 그레이 래스터 (상류 `sharp` 대체) |
| `frameMatch.ts` | ZNCC coarse→fine + 부엽 마진 (상류 `frame-match.mjs` 이식) |
| `sweepPlan.ts` | 줌 앵커 × 클릭 표적 · **시드 z 규칙** |
| `cameraLock.ts` | 유언장 — 홈 자세를 디스크에 먼저 남긴다 |
| `calibrationJob.ts` | 잡 러너 (start/status/stop · 홈 복귀 · 취소) |
| `calibrationComponent.ts` | 바깥 표면 + `mint`(발행) |

**솔버는 만들지 않았다.** `buildCalibration`·`solveZoom` 은 이미 벤더링돼 있었고 아무도 쓰지
않았다 — 501의 진짜 원인은 수학이 아니라 JPEG 디코딩이었다.

#### ★ ffmpeg 디코딩 (마스터 확정)

```
ffmpeg -hide_banner -loglevel error -f image2pipe -i pipe:0 -pix_fmt gray -f rawvideo pipe:1
```

`rawvideo` 출력에는 헤더가 없어 치수를 따로 알아야 한다. **JPEG 헤더의 SOF 마커를 직접 읽고,
`data.length === width*height` 를 단언한다** — 그 단언이 "헤더 파서와 ffmpeg 가 같은 그림을
봤다"는 증거이고, 어긋나면 계산을 이어 가는 대신 그 샘플을 버린다.

| 대안 | 왜 아닌가 |
|---|---|
| `ffprobe` 한 번 더 | 샘플마다 왕복이 두 배(112샘플 × 2프레임) |
| `-vf scale=1920:1080` 강제 | **정밀도를 잃는다** — 재는 신호 전체가 수십 픽셀 폭이다 |

`probe()` 는 **한 번만 묻고 기억한다** — `capabilities()` 는 화면이 폴링하는 경로라, 물을 때마다
spawn 하면 버튼 하나 그리는 데 초당 여러 번 프로세스가 뜬다.

#### 반드시 지킨 넷 (전부 상류가 실제로 당한 사고)

1. **full 은 보정 없이(raw) 조준한다** — 도출하려는 보정을 통과해서 재면 안 된다
2. **verify 는 설치된 보정을 통과해서 조준한다** — 답할 질문이 "이 보정이 맞나"이므로
3. **줌 앵커는 기기 눈금** — 범위 밖 앵커는 `rc=0` 으로 조용히 최망원에 클램프된다
4. **카메라를 반드시 돌려준다** — 실패·취소·프로세스 사망 전부. 그래서 유언장이 있고,
   `index.ts` 가 기동 시 남은 유언장을 이행한다

#### ★ 살아 있던 결함을 고쳤다

`BridgeCoreProvider.center()` 가 클릭 픽셀을 **게인 없이** 넘기고 있었다. 상류가 실측한
*z8000 이상 약 10% 부족 회전*이 그대로 살아 있었고, **증상이 조용해서**(중앙 근처는 멀쩡)
아무도 신고하지 않는 종류였다.

이제 `aimPixel()` 을 통과하고 응답에 `gain` 이 실린다 — **1 이면 "보정이 없었다"는 것도 사실로
보고한다.** 조용한 보정은 조용한 미보정만큼 나쁘다.

**게인 표가 없으면 k=1 이다.** 내장 `CENTERING_GAIN_TABLE` 을 기본값으로 들지 않는다 — 그 표는
cam-001 한 대의 곡선이고 **단조가 아니라**(z8000 에서 1.11, z16384 에서 0.765) 다른 렌즈에
씌우면 망원 오차를 **악화**시킨다.

#### 게이트 3종 (소프트웨어 센터링)

| 게이트 | 왜 |
|---|---|
| 실측 `zoomHfov` 표가 있어야 켠다 | 화각을 모르면 픽셀을 각도로 못 바꾼다 |
| 표가 기기 줌 **범위를 덮어야** 한다 | 부분 표 = 표 밖 줌에서 **12배 과회전**(상류 실측) |
| 틸트 전량 클램프는 **422 + 사람 문장** | 무이동이라 정착 대기 10초 뒤 **원인 불명 502** 가 된다 |

> 모서리는 사이드카가 개별적으로 버린다. 오버레이는 **받은 선분만 잇는다.**

어휘의 경계는 상류와 같다: 봉투(`cameraId`·`capturedAt`·`count`·`model`·`latencyMs`)는 우리 것,

이유는 **무엇을 기준으로 잰 값인지가 곧 값의 의미**이기 때문이다.

## 3. 독립을 어떻게 강제했는가

```
   ┌─ 캘리브레이션 ─┐                      ┌─ 센터라이징 ─┐
   │   verify 모드  │                      │  운영 조준   │
   └───────┬────────┘                      └──────┬───────┘
           └──────────┬───────────────────────────┘
                      ▼
        vendor/baro-profile (순수 함수 · 이미 있음)      ① 계산의 만남
          applyCenteringGain · pixelToPtzDelta · hfovFromZoomPos

   캘리브레이션 ──publish──▶  profiles/  ──read──▶  센터라이징   ② 데이터의 만남
```

`test/componentIndependence.test.ts` 가 넷을 검사한다.

1. 세 디렉토리 사이 import **0건**
2. 허용된 아래 층만 본다(옆이나 위를 보지 않는다) · **외부 npm 패키지 import 0건**
3. 게인 함수를 **각자** 부른다 — 한 컴포넌트가 대신 불러 주지 않는다
4. 브리지 코어에 기하·이미지 처리가 **없다**(`pixelToPtzDelta`·`applyCenteringGain`·
   `hfovFromZoomPos`·`buildCalibration` 문자열이 그 파일에 나타나면 실패)

**컴포넌트 C 는 어느 쪽과도 만나지 않는다.** 사이드카는 자기 캘리브레이션 파일을 쓰고, 그것은
우리 발행본과 **다른 것**이다(§8 미해결).

## 5. 구현 중 잡은 결함

| 무엇 | 어떻게 드러났나 |
|---|---|
| **`center()` 에 게인이 없었다** | 설계 단계에서 소스를 읽다 발견. 증상이 조용한 종류 |
| **벤더 타입 선언이 실제 `.mjs` 와 어긋나 있었다** | `applyCenteringGain`·`buildCalibration`·`solveZoom` 의 시그니처가 틀려 있었다(인자 개수·이름). strict 코드에서 부르자 즉시 드러남 |
| **`ProfileStore.listRevisions` 의 catch 가 경로 검증 예외를 삼켰다** | 저장소 밖을 가리키는 id 가 "리비전 없음"으로 **조용히 성공**했다. 경로 안전 테스트가 잡았다 |
| **DB 의 `intrinsics` 가 설정과 다른 규칙으로 읽혔다** | `parseIntrinsics` 가 배열이기만 하면 통과시켜, 앵커 1개짜리 표(보간 불가)와 `centeringGain` 누락이 조용히 지나갔다. `normalizeIntrinsics` 로 통일 |
