# Park3D 제어/영상 포트 분리 정정

- 날짜: 2026-08-06
- 브랜치: `fix/park3d-stream-port-per-camera`
- 계기: 옵션 화면의 「제어 URL」이 RPC 서버 주소인지 카메라 스트림 주소인지 묻는 질문. 확인해 보니
  코드·문서가 **"제어와 영상이 같은 포트"** 라는 옛 전제를 들고 있었고, 실제 서버는 이미 분리돼 있었다.

---

## 1. 무엇이 사실인가 — 라이브 서버 실측

대상: `192.168.0.125` (언리얼 Park3D 시뮬레이터). 읽기 전용 호출만 했다(PTZ 이동 없음).

| 요청 | 13510 | 13601 · 13602 |
|---|---|---|
| `POST /rpc` `cam.getPTZ` | **200** `{"result":{"pan":113.8,"tilt":6,"zoom":2.9}}` | **200** `multipart/x-mixed-replace; boundary=park3dframe` — 영상이 온다 |
| `GET /stream` | 200 multipart | 200 multipart |

- **제어는 RPC 서버 하나: 13510.** 카메라 대수와 무관하다.
- **영상은 카메라별 포트: 13601~13650 = `13600 + camId`** (camId 는 1-based). 마스터 확정.
- `HEAD /stream` 은 13510 에서 404 를 돌려준다 — UE 내장 HTTP 서버가 HEAD 를 처리하지 않기 때문이고,
  `GET` 은 200 이다. 진단할 때 HEAD 결과로 판단하면 안 된다.

### 왜 이 오배선이 특히 위험한가

스트림 포트(13601~)는 **경로를 보지 않는다.** `POST http://호스트:13601/rpc` 를 보내도 404 가 아니라
200 + MJPEG 스트림이 온다. 그래서 제어 URL 에 스트림 포트를 적으면:

1. TCP 연결 성공, HTTP 200 → "연결은 되는 것 같다"
2. 본문이 JSON 이 아니므로 `park3dRpcClient.ts` 의 JSON 파싱에서 실패
3. 사용자에게는 `Park3D RPC 응답을 해석할 수 없습니다` 만 보인다

**연결은 되는데 PTZ 만 안 먹는** 형태라 원인이 포트라는 걸 짚기 어렵다. 그래서 설정 화면에서 미리 막는다.

## 2. 변경 내용

### 2-1. `SettingMain/web/optionsDb.js` — 경고 로직 (핵심)

**전:** `portPairWarning` 이 park3d-rpc 를 **무조건 통과**시켰다. "같은 포트라 +10 규칙을 적용하면 거짓 경고가 된다"는
당시로선 맞는 이유였지만, 그 결과 park3d 카메라는 **어떤 포트 오배선도 잡히지 않았다.**

**후:** 시그니처에 `camId` 를 더하고, park3d-rpc 전용 검증 두 가지를 넣었다.

```js
function portPairWarning(controlUrl, streamUrl, kind, camId) {
  // ... http(s) 인지 · 포트가 있는지 확인 (종전과 동일)

  if (kind === 'park3d-rpc') {
    const STREAM_PORT_BASE = 13600;
    const STREAM_PORT_LAST = 13650;
    // ① 제어 칸에 영상 포트를 적는 사고가 가장 흔하고 가장 안 보인다 — 이쪽을 먼저 본다.
    if (controlPort > STREAM_PORT_BASE && controlPort <= STREAM_PORT_LAST) {
      return ` ⚠ ${controlPort} 은 영상 포트입니다 — 제어 URL 에는 RPC 서버 포트(예: 13510)를 적으십시오`;
    }
    const camNumber = Number(camId);
    if (!Number.isInteger(camNumber) || camNumber < 1) return '';   // camId 를 아직 안 적었다
    const expected = STREAM_PORT_BASE + camNumber;
    if (streamPort === expected) return '';
    // ② 영상 포트가 camId 와 어긋나면 다른 카메라를 보게 된다
    return ` ⚠ camId ${camNumber} 의 영상 포트는 ${expected} 입니다 — 지금 ${streamPort} 는 다른 카메라를 봅니다`;
  }

  // hucoms · backend-core 의 「영상 = 제어 + 10」 은 문자 그대로 보존
}
```

**포트 상수를 함수 안에 둔 이유가 있다.** 테스트가 이 함수의 본문만 소스에서 떼어 내 `new Function` 으로
**실제 평가**한다(브라우저 모듈이라 통째로 import 할 수 없다). 상수를 파일 최상위에 두면 떼어 낸 본문이
참조하지 못해 ReferenceError 로 죽는다. 기존 주석이 "최상위 순수 함수로 둔다"고 못박아 둔 것과 같은 이유다.

### 2-2. `SettingMain/web/optionsDb.js` — `streamHint()` 의 값 출처

```js
const kind = selected()?.kind;        // 전: 저장된 행
const kind = $('camKind').value;      // 후: 화면의 지금 값
```

`camKind` 의 `change` → `streamHint` 배선은 **이미 있었지만**, kind 를 저장된 행에서 읽는 바람에
종류를 바꿔도 힌트가 옛 종류로 계산됐다(배선이 헛돌았다). 새 경고가 종류에 따라 갈리므로 이 상태를 두면
경고 자체가 거짓말을 한다. `draft()` 가 저장하는 값과도 같은 출처가 됐다.

camId 도 같은 이유로 `$('camPark3d').value` 를 쓰고, `camPark3d` 에 `input` → `streamHint` 배선을 새로 걸었다
(없어서 camId 를 고쳐도 경고가 갱신되지 않았다).

안내 문구:

```
전: http:// → MJPEG 중계 (Park3D 는 같은 포트의 /stream 을 중계합니다)
후: http:// → MJPEG 중계 (Park3D 영상은 카메라별 포트 13600 + camId 입니다 — 제어는 RPC 서버 하나)
```

### 4-3. 남은 위험

- **포트 공식의 표본.** `13600 + camId` 는 마스터 확정이고 camId 2 ↔ 13602 를 실측했지만,
  50대 전수를 확인한 것은 아니다. 시뮬레이터가 매핑 규칙을 바꾸면 경고가 거짓 양성이 된다.
  그때 고칠 곳은 `portPairWarning` 안의 `STREAM_PORT_BASE` 한 곳이다.
- **브라우저 실동작 미확인.** 테스트가 소스를 읽어 검사하는 구조라, 화면에서 경고가 실제로 렌더되는지는
  `npm start` 후 옵션 페이지에서 사람이 봐야 한다.
