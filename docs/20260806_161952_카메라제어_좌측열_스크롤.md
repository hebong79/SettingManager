# 카메라 제어 화면 — 좌측 조작 열만 스크롤, 영상 열은 고정

- 날짜: 2026-08-06
- 요청: "왼쪽 패널에 스크롤바를 붙여라. 우측은 고정, 좌측만 스크롤로 움직이게."
- 대상 화면: `/` (카메라 제어, `web/index.html`)

---

## 1. 문제

좌측에 조작 카드가 4장(대상 선택 · 현재 PTZ · PTZ 제어 · 절대 좌표 이동)이라 세로로 길다.
지금까지는 `.layout` 그리드의 두 열이 함께 페이지 스크롤을 탔기 때문에, **방향 패드를 쓰려고 아래로 내리면
우측 영상이 화면 밖으로 나갔다.** 카메라를 움직이면서 그 결과를 볼 수 없는 상태였다.

## 2. 변경 내용

### 2-1. `web/index.html` — 클래스 2개 부여

레이아웃의 두 열은 클래스 없는 `<div>` 였다. CSS 를 붙일 자리가 없어 이름을 준다.

```html
<div class="control-column">   <!-- 왼쪽: 제어 -->
<div class="stream-column">    <!-- 오른쪽: 영상 · 주차면 -->
```

구조·순서·id 는 하나도 건드리지 않았다(정적 계약 테스트가 그 순서를 고정하고 있다).

### 2-2. `web/app.css` — 데스크톱 폭에서만 좌측 열을 가둔다

```css
@media (min-width: 1101px) {
  .control-column {
    max-height: calc(100vh - 100px);
    overflow-y: auto;
    padding-right: 6px;                          /* 스크롤바가 카드 테두리를 덮지 않게 */
    scrollbar-width: thin;
    scrollbar-color: var(--line) transparent;    /* 밝은 기본 스크롤바가 어두운 판에서 튄다 */
  }
  .stream-column { position: sticky; top: 80px; }
}
```

**높이 `100vh - 100px` 의 근거:** 상단바 60px(패딩 12+12 + 내용 35 + 테두리 1) + `main` 위 여백 20px 아래에서
열이 시작하고, 아래 여백 20px 를 남긴다 → 80 + 20 = 100px.

**`@media (min-width: 1101px)` 로 감싼 이유:** 1100px 이하에서는 `.layout` 이 한 열로 접힌다(기존 규칙).
그 상태에서 높이를 가두면 좌우가 아니라 **조작 카드 전체가 작은 상자 안에 갇힌다.** 접히는 폭에서는
종전처럼 페이지 전체가 스크롤되게 둔다.

**`stream-column` 의 `sticky`:** 좌측이 자체 스크롤이 되면 페이지 높이는 대개 화면을 넘지 않으므로
우측은 가만히 있는다. 다만 창이 아주 낮아 우측(영상 + 주차면 리스트)이 화면보다 길어지면 페이지가 스크롤되는데,
그때도 영상이 위에 붙어 있도록 `sticky` 를 건다. 주차면 탐색 화면의 `#discoveryViewer` 와 같은 수법이다
(그쪽은 `top: 72px`, 이쪽은 열 시작 위치와 정확히 같은 `80px` 이라 평소에는 1px 도 움직이지 않는다).

## 3. 테스트

`test/server.test.ts` 에 정적 계약 테스트 1건 추가 — **통과**.

```
✓ 카메라 제어 CSS는 좌측 조작 열만 스크롤시키고 영상 열은 붙여 둔다
```

검증 항목:

| 검증 | 이유 |
|---|---|
| `index.html` 에 `class="control-column"` · `class="stream-column"` 존재 | 클래스가 빠지면 CSS 규칙이 **조용히 아무 데도 적용되지 않는다** |
| `.control-column` 규칙 본문에 `max-height: calc(100vh - 100px)` · `overflow-y: auto` | 스크롤의 실체 |
| `.stream-column { position: sticky; top: 80px; }` | 우측 고정 |
| 규칙이 `@media (min-width: 1101px)` 블록 안에 있다 | 접히는 폭에서 카드가 갇히는 회귀 방지 |

- `npm run typecheck` 통과.
- `test/server.test.ts` · `test/discoveryUi.test.ts` · `test/optionsDbUi.test.ts` 동시 실행: **97 통과 / 17 실패.**
  실패 17건은 **전부 이 변경 이전부터 깨져 있던 것**이다(기기 추가·삭제 5 · 연결 테스트 3 · 본문 인코딩 2 ·
  설정 저장 6 · `/options` 1). 카메라 정본이 `camera_info` 테이블로 옮겨지면서 사라진 옛 DOM·옛 라우트를
  기대하는 테스트들로, 레이아웃과 무관하다. **이번 변경으로 새로 깨진 테스트는 없다.**
- 구동 중인 서버(`127.0.0.1:13030`)가 바뀐 `app.css`·`index.html` 을 실제로 내보내는 것까지 확인했다.

> **브라우저 실제 렌더는 사람이 봐야 한다.** 테스트는 소스를 읽어 검사하는 구조라 픽셀을 보지 못한다.
> CSS 는 브라우저가 캐시하므로 **강제 새로고침(Ctrl+F5)** 후 확인할 것.

## 4. 영향도 분석

| 대상 | 영향 |
|---|---|
| `/discovery` · `/options` · `/dbtable` | **없음.** 새 선택자 2개는 `index.html` 에만 있다. 기존 `.layout` · `.discovery-layout` 규칙은 한 글자도 안 건드렸다 |
| `control.js` | **없음.** DOM 조회는 전부 id 기반이고 id·순서를 바꾸지 않았다 |
| 서버 · API · 드라이버 | **없음.** 정적 파일 2개만 바뀌었다 |
| 1100px 이하(노트북 세로·모바일) | **없음.** 미디어쿼리 밖이라 종전과 동일하게 페이지 전체가 스크롤된다 |
| 기존 테스트 | 추가 1건 외 변경 없음 |

## 5. 남은 위험

- **높이 100px 는 상단바 높이에 묶인 상수다.** 상단바 패딩·폰트·nav 버튼 크기를 바꾸면 좌측 열 아래가
  화면 밖으로 조금 나가거나 여백이 뜬다. 그때 고칠 곳은 `.control-column` 의 `max-height` 와
  `.stream-column` 의 `top` **두 곳**이다(값이 서로 맞물려 있다).
- 좌측 열 안에서 스크롤한 위치는 카메라를 바꿔도 초기화되지 않는다. 지금은 문제가 아니지만,
  카드 개수가 크게 늘면 "왜 화면이 중간에 떠 있지"로 보일 수 있다.
