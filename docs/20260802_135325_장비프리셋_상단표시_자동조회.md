# 장비 프리셋 상단 표시 및 자동 조회

## 개요

기존 장비 프리셋 카드는 `현재 PTZ` 뒤의 독립 카드여서 첫 화면에서 보이지 않을 수 있었고, 초기 진입·카메라 변경 시 자동 조회 없이 수동 새로고침만 가능했다. 이번 변경은 읽기 전용 장비 프리셋 블록을 `대상 선택` 카드 안의 `cameraSelect` 다음, 로컬 `presetSelect` 앞에 배치하고 자동 조회를 연결한다.

근거 문서는 `_workspace/01_architect_plan.md`, `_workspace/02_developer_changes.md`, `_workspace/03_qa_report.md`와 실제 변경 파일이다.

## 변경 클래스·함수와 로직 의도

- `SettingMain/web/index.html`: 독립 장비 프리셋 카드를 제거하고 `devicePresetTitle`, `devicePresetTag`, `devicePresetArea`, `devicePresetRefresh` 식별자를 유지한 읽기 전용 section을 대상 카드에 삽입했다. 상태 영역은 `role="status"`, `aria-live="polite"`, `aria-atomic="true"`를 사용하고, 재시도 버튼에는 `type="button"`, `aria-controls`, 접근 가능한 이름을 부여한다.
- `SettingMain/web/control.js`의 `main()`: `loadCameras()` 성공 후 선택 카메라의 `loadDevicePresetCapability()`를 자동 호출한다. 장비 조회 실패가 다른 초기 데이터 로드를 중단시키지 않도록 독립 오류 상태로 끝낸다.
- `SettingMain/web/control.js`의 `onCameraChange()`: 카메라 ID와 활성 카메라 흐름을 갱신한 뒤 새 카메라에 대해 같은 GET 조회를 자동 실행한다. 이전 후보는 즉시 무효화한다.
- `SettingMain/web/control.js`의 `loadDevicePresetCapability()` 및 상태 렌더링 경로: 요청 시 카메라 ID와 세대 번호를 캡처하고, 응답·오류·`finally`에서 현재 카메라와 최신 세대가 일치할 때만 state/DOM/버튼을 갱신한다(stale guard). 조회 중에는 `aria-busy=true`와 disabled, 성공·미지원·실패는 태그와 본문으로 함께 표현한다. 엄격한 validator를 통과한 실제 성공 응답만 광고된 후보를 표시하며, 후보는 `등록 여부/이름 미확인`으로 읽기 전용 표시한다.

## 입출력·외부 계약

기존 `api.devicePresetCapability(cameraId)`와 `GET /api/device-preset-capability?cameraId=...` 계약을 그대로 사용한다. 정상적인 지원 응답에서만 장비가 광고한 범위를 입출력으로 렌더링하고, 미지원 응답은 `미지원`으로 표시한다. 현재 실 카메라 응답은 `real-camera-2`에 대해 HTTP 502, `{"error":"카메라 통신 실패: fetch failed"}`였으며, 이를 데이터 성공으로 취급하지 않는다.

502·계약 오류에서는 `state.devicePresetCapability = null`, 기존 후보 DOM 제거, `조회 실패` 태그와 재시도 안내를 표시한다. `#1`~`#128`을 합성하거나 이전 카메라 후보를 잔존시키지 않는다. 수동 버튼은 동일 함수를 재호출하며 자동 조회 중 중복 클릭은 disabled로 차단한다.

장비 후보는 로컬 프리셋 데이터가 아니다. `presetSelect` 및 `api.presets`, `gotoPreset`, `addPreset`, `updatePreset`, `removePreset` 계약과 state를 분리해 유지한다.

## 영향도

직접 영향 파일은 `SettingMain/web/index.html`(구조·ARIA), `SettingMain/web/control.js`(자동 조회·상태·stale guard), `SettingMain/web/app.css`(section 경계, 소제목/태그, 180px 내부 세로 스크롤, focus 가능 목록), `SettingMain/test/server.test.ts`(정적 DOM/동작 회귀 계약)이다. `SettingMain/web/api.js`의 기존 API 함수는 소비만 하며 계약을 변경하지 않았다.

후속 소비·생산 경계는 장비 capability 서버 endpoint와 기존 클라이언트 API이며, 형제 `AgentVLA/ParkAgent/SettingAgent` 및 장비 firmware 계약은 수정하지 않았다. 서버·API 클라이언트 구현, 설정 포맷, 공유 타입, 의존성에는 이번 작업의 변경이 없다. 다른 카드의 PTZ·영상·주차면 동작과 로컬 프리셋 저장/이동/추가/삭제도 변경하지 않는다.

후보 목록은 내부 스크롤로 긴 목록이 첫 화면을 밀어내지 않게 하며, 색상만으로 상태를 구분하지 않고 텍스트·ARIA를 함께 제공한다. 실제 브라우저에서의 시각 배치·키보드 상호작용은 별도 검증 대상이다.

## 비범위

- 502 원인 또는 장비/서버 endpoint 수정
- 장비 프리셋 등록 여부·이름의 추가 조회
- 장비 후보의 이동·등록·저장·삭제 기능
- 실패 시 `#1..#128` fallback 생성 또는 다른 카메라 캐시 표시
- 로컬 프리셋 모델·저장소·명령 계약 변경
- `AgentVLA/ParkAgent/SettingAgent` 및 운영 카메라/firmware 변경

## 테스트 및 검증 결과

QA 기록 기준 `npm run typecheck` 통과, `npm test` 9개 파일·201개 테스트 통과, `npm run build` 통과, `git diff --check` 통과(CRLF 변환 경고만 존재)했다. 실행 중인 기존 `127.0.0.1:13030` 서비스는 중지·재시작하지 않고 `GET /`와 capability GET만 수행했으며, 실제 502 응답을 확인했다. 카메라 제어·프리셋 명령·활성 카메라/구성 변경은 수행하지 않았다.

in-app Browser가 `Browser is not available: iab`로 제공되지 않아 420px 시각 배치, 실제 DOM 실행 화면, 재시도 클릭, 지연 응답 경쟁 및 키보드 상호작용은 브라우저에서 검증하지 못했다. 해당 항목을 성공으로 간주하지 않으며, 소스·정적 HTML·HTTP·단위 테스트 근거로만 판정했다.
