# 시뮬레이터 뷰에서 언리얼처럼 마우스로 화면 제어가 되는가

- 일시: 2026-08-08 15:21:35
- 질문: 「시뮬레이터 뷰에서 언리얼에서처럼 마우스로 화면 제어 할 수 있는가?」
- 대상 화면: `SettingMain/web/simtool.html` · `simtool.js` (시뮬레이터 툴 → 시뮬레이터 뷰)

## 1. 한 줄 답

**지금 보고 있는 메인 뷰(`simulator-99`)에서는 안 된다.** 언리얼 쪽에 그 뷰의 자세를
읽거나 바꾸는 RPC(`view.*`)가 아예 없어서, 마우스를 끌어도 **보낼 명령이 없다.**

**PTZ 카메라 영상(포트 13601 이상)으로 바꾸면, 지금 있는 RPC만으로 만들 수 있다.**
다만 언리얼 에디터의 자유비행이 아니라 **삼각대 위 PTZ 회전**이다.

## 2. 왜 메인 뷰는 안 되는가 — 근거

영상은 나온다. 2026-08-08 정정대로 `simulator-99`(스트림 basePort **13600**)가 시뮬레이터
메인 카메라이고, 스크린샷의 그림이 그것이다. 막힌 것은 **영상이 아니라 제어**다.

| 근거 | 위치 |
|---|---|
| `view.get` 실측 결과가 `-32601 미등록 method` | `docs/20260807_173103_주차면페이지_시뮬레이터툴_설계서.md:138` |
| 메인 뷰의 위치·방향을 주는 RPC 가 82개 중 하나도 없다 | `SettingMain/web/simtool.js:282-302` (`projectionCamId()` 주석) |
| 그래서 메인 영상 위에서는 **클릭 피킹조차** 성립하지 않아 화면이 그 사실을 말한다 | `SettingMain/web/simtool.js:315-318` |
| 허용 메서드 카탈로그에 `view.*` 계열이 없다 | `SettingMain/src/sim/simCatalog.ts:51-140` |

즉 메인 뷰는 **읽기 전용 창**이다. 마우스 제어를 하려면 언리얼에 신설이 필요하다 —
설계서 §4.3 이 이미 4개를 명세해 두었다(`view.get` / `view.set` / `view.pick` / `view.lookAt`).

## 3. PTZ 카메라 영상이면 무엇이 되는가 — 지금 있는 RPC

`SettingMain/src/sim/simCatalog.ts` 에 살아 있는 것들:

| 마우스 동작 | 부를 RPC | 상태 |
|---|---|---|
| 좌드래그 → 시선 회전 | `cam.setPTZ {camId, pan, tilt, zoom}` | ✅ 동작 |
| 휠 → 확대·축소 | `cam.setZoom` 또는 `cam.setFOV` | ✅ 동작 |
| 우드래그 → 카메라 평면 이동 | `cam.setPosition {camId, pos:{x,y,z}}` | ✅ 동작 |
| 휠클릭·수정키 → 높이 | `cam.setHeight {camId, height}` | ✅ 동작 |
| 현재 자세 읽기 | `cam.getPTZ` | ✅ 동작 |

이미 `simtoolCam.js` 의 방향 패드가 이 경로를 쓰고 있으므로 **새 서버 작업 없이 화면 쪽만**
붙이면 된다.

### 그래도 언리얼과 같지는 않다

1. **궤도 회전(orbit)이 없다.** 카메라는 제자리에서 돌 뿐, 어떤 지점을 중심으로 돌지 못한다.
   `view.lookAt` 이 없으므로 "이 차를 중심으로 돌려보기"는 안 된다.
2. **줌은 달리(dolly)가 아니라 화각**이다. 휠을 굴리면 앞으로 가는 게 아니라 망원이 된다.
3. **tilt 부호가 반대다.** 양수가 하향이라 위로 끌면 부호를 뒤집어야 한다
   (`simtoolCam.js:162-177` 에 같은 함정이 기록돼 있다).
4. **좌표계는 Z-up**(언리얼). Unity 기준으로 베끼면 높이 칸에 앞뒤 값이 들어간다.

## 4. 가장 큰 실제 장애물은 반응 속도다

언리얼 에디터의 뷰포트는 **로컬 렌더링**이라 마우스에 즉시 붙는다. 여기는 다르다:

```
마우스 이동 → 브라우저 → SettingManager(/api/sim/rpc) → 시뮬레이터 RPC → 언리얼 카메라 이동
                                                                      ↓
화면 갱신  ←  MJPEG 스트림(13600+camId)  ←  인코딩  ←  렌더
```

왕복이 두 번 들어간다. `simtoolCam.js:267-269` 에 이미 같은 교훈이 적혀 있다 —
슬라이더를 `input` 마다 보냈더니 **드래그 한 번에 수십 개 명령이 나가 시뮬레이터가 밀렸다.**
그래서 지금은 손을 뗄 때(`change`) 한 번만 보낸다.

마우스 드래그로 하려면 이 문제를 정면으로 다뤄야 한다:

- **한 번에 한 요청만** 띄운다(in-flight 하나, 다음 것은 최신 값으로 덮어쓰기).
- `requestAnimationFrame` 또는 ~50~100ms 스로틀로 전송 빈도를 묶는다.
- 화면에는 **보낸 목표값**을 먼저 표시하고, 영상은 늦게 따라오는 것을 정상으로 안내한다.

이 처리 없이 붙이면 "끌면 화면이 한참 뒤에 미끄러진다"가 되어 오히려 방향 패드보다 나쁘다.

## 5. 결론과 선택지

| 선택지 | 필요 작업 | 결과 |
|---|---|---|
| **A. PTZ 영상 위 마우스 제어** | 화면(JS)만. 서버·언리얼 변경 없음 | 좌드래그 회전 · 휠 줌 · 우드래그 이동. 스로틀 필수 |
| **B. 메인 뷰 자유비행** | 언리얼에 `view.get`/`view.set`(+`view.pick`) 신설 → 서버 카탈로그 등록 → 화면 | 진짜 언리얼식 조작. 클릭 피킹도 함께 풀린다 |
| C. 현행 유지 | — | 방향 패드 + 슬라이더 |

**B 는 부수 효과가 크다.** `view.pick` 이 생기면 메인 뷰에서 클릭으로 차량 배치·타겟점
설치가 되어, 지금 "메인 영상에서는 클릭이 안 된다"고 안내만 하는 자리가 전부 열린다
(설계서 §4.4 의 여러 항목이 `view.*` 대기 중이다).

## 6. 주변 영향 분석

이 문서는 **조사·답변이며 코드 변경이 없다.** 다만 위 선택지를 실행할 경우의 영향 범위:

- **A 를 택하면**: `SettingMain/web/simtool.js`(뷰포트 이벤트) 와 `simtoolCam.js`(PTZ 상태
  소유자)가 바뀐다. 두 곳이 같은 `ptz` 상태를 만지게 되므로 **소유자를 한쪽으로 정해야**
  한다 — 지금 `ptz` 는 `simtoolCam.js` 안의 지역 상태다. `simtool.js` 의
  `viewportClick`(mousedown)과 드래그가 같은 버튼을 다투므로 **클릭 모드와의 교통정리**도
  필요하다(예: 드래그 임계값 이하 이동은 클릭으로 본다).
- **B 를 택하면**: `SettingMain/src/sim/simCatalog.ts` 에 `view.*` 4개 추가 →
  `simtool.js:117-135` 의 미등록 메서드 경고가 자동으로 이 4개를 감시한다.
  `projectionCamId()` 의 "메인은 자세를 알 수 없다" 분기와 `updateClickNote()` 의 경고
  문구가 함께 바뀐다. 서버의 `/api/sim/pick`(`simRoutes.ts`)은 **웹 기하 계산 대신
  `view.pick` 위임**으로 갈지 결정이 필요하다.
- **시뮬 독립 경계**(`test/simIndependence.test.ts`)는 어느 쪽도 건드리지 않는다 —
  `src/sim/` 이 카메라·코어·DB 를 import 하지 않는 규칙 그대로다.
