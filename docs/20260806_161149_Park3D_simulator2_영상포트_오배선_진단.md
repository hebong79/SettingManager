# Park3D `simulator-2` 영상 포트 오배선 진단 — "13510 제어가 전혀 안 된다"

- 날짜: 2026-08-06
- 계기: "192.168.0.125 13510 포트의 카메라 제어가 전혀 안 된다"는 신고
- 결론: **코드 결함 아님.** `camera_info` 에 저장된 영상 URL 이 다른 카메라를 가리켜,
  제어는 정상인데 화면만 안 움직인 것. 사용자가 DB 값을 고쳐 정상 동작 확인.
- 코드 변경: **없음** (이 문서 1건만 추가)

---

## 1. 제어 경로는 정상이었다 — 실측

라이브 시뮬레이터(`192.168.0.125`)와 구동 중인 SettingManager(`127.0.0.1:13030`)에 직접 요청했다.

| 확인 | 결과 |
|---|---|
| `POST 192.168.0.125:13510/rpc` `cam.getPTZ {camId:1}` | 200 `{pan:27.8, tilt:8.7, zoom:1.62}` |
| `POST /api/ptz/nudge` `simulator-2` (camId 1) pan +2° | 27.8° → **29.8°** 실제 이동, `settled:true` |
| `POST /api/ptz/nudge` `simulator-3` (camId 2) pan +2° | 113.8° → **115.8°** 실제 이동, `settled:true` |

RPC 서버 · `park3dRpcClient.ts` · `ptzRoutes.ts` · `control.js` 의 패드 배선까지 어느 단계도 문제가 없었다.
**진단으로 움직인 두 카메라는 모두 원래 좌표(camId 1 = 27.8/8.7/1.62, camId 2 = 113.8/6/2.9)로 복원했다.**

## 2. 진짜 원인 — 저장된 영상 URL 이 남의 카메라를 본다

`config/setup.db` · `camera_info` 의 당시 상태:

| cam_uuid | 이름 | park3d_cam_id | 제어 URL | 영상 URL(`rtsp_url`) |
|---|---|---|---|---|
| `simulator-2` | UE-시뮬2(cam1) | **1** | `…:13510` ✅ | **`…:13602/stream`** ❌ (13601 이어야 함) |
| `simulator-3` | UE-시뮬2 (camId 2) | 2 | `…:13510` ✅ | `…:13602/stream` ✅ |

`rtsp_url` 은 `configCameras.ts:28` 에서 그대로 `streamUrl` 이 된다. 그래서 「UE-시뮬2(cam1)」을 고르고
방향키를 누르면 — 명령은 camId 1 로 정확히 가서 **실제로 움직이지만**, 화면에 뜨는 영상은 camId 2 것이라
그대로다. 사용자에게는 오류 한 줄 없이 **"제어가 전혀 안 된다"** 로만 보인다.

### 2-1. `13600 + camId` 규칙 재검증

camId 1 을 pan +30° 돌리고 두 포트의 첫 MJPEG 프레임을 떠서 비교했다.

```
이동 전   13601: 72921 bytes sha1=5b05c8c01e21 | 13602: 61071 bytes sha1=69b451cde52a
이동 후   13601: 87155 bytes sha1=ee3cb7e35f74 | 13602: 61071 bytes sha1=69b451cde52a  ← 바이트 동일
```

camId 1 을 움직였는데 **13602 프레임은 sha1 까지 완전히 동일**했다 → 13602 는 camId 1 이 아니다.
camId 2 를 +30° 돌렸을 때는 13602 프레임이 바뀌었다(61585 → 51553).

> **증거의 한계(기록해 둔다).** 두 번째 실험에서 camId 1 을 건드리지 않았는데도 13601 프레임이 바뀌었다.
> 시뮬레이터 장면 자체에 움직임(차량 등)이 있다는 뜻이므로, "프레임이 바뀌었다"는 약한 증거다.
> 반대로 **"움직였는데 바이트가 완전히 같다"** 는 강한 증거이고, 판정은 그쪽에만 기댔다.

## 3. 조치

사용자가 옵션 화면에서 `simulator-2` 의 영상 URL 을 `…:13601/stream` 으로 고치고 정상 동작을 확인했다.
**저장소 코드는 한 줄도 고치지 않았다** — 고칠 것이 없었기 때문이다:

- `park3dRpcClient.ts` 의 로직·주석: 이미 정확
- `config.example.json`: 이미 `13510` / `13601` (2026-08-06 앞선 커밋에서 정정됨)
- `optionsDb.js` 의 `portPairWarning`: 이 행에 대해 **경고를 이미 띄우고 있었다**

즉 예방 장치는 앞선 커밋(`dbe4348`)에서 이미 들어갔고, 그때 "이미 저장된 `camera_info` 행은 자동으로
고쳐지지 않는다"고 남긴 잔여 위험이 그대로 현실화한 사례다.

## 5. 남은 위험

- **같은 함정이 다시 난다.** 화면 경고는 사람이 봐야 작동한다. 저장 시점에 경고를 **차단(blocking)** 으로
  올리거나, 기동 시 `park3d-rpc` 행의 `13600 + camId` 불일치를 로그로 한 번 찍어 주는 보강을 고려할 수 있다.
  (이번에는 요청 범위 밖이라 하지 않았다.)
- `simulator-2`/`simulator-3` 가 같은 시뮬의 다른 카메라인데 이름이 헷갈린다 — 라벨에 camId 를 넣어 두면
  선택 실수가 줄어든다.
