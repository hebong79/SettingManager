## 2. 독립 경계 — 지시 7

```
web/simtool*.js
      │  fetch('/api/sim/rpc')        ← 표면은 이것 둘뿐
      ▼
src/api/routes/simRoutes.ts           driverFor·db·cameras 를 만지지 않는다
      │
src/sim/simRpcClient.ts               JSON-RPC 봉투·오류 매핑
src/sim/simCatalog.ts                 허용 메서드 79종
      │  POST http://<sim>:13510/rpc
      ▼
   언리얼 Park3D RPC
```

**말로 두지 않고 검사한다** (`test/simIndependence.test.ts` · `test/simtoolUi.test.ts`):

| 검사 | 왜 |
|---|---|
| `src/sim/**` 가 `devices/`·`core/`·`db/`·`detectors/`… 를 import 하지 않는다 | 다음 사람이 "카메라 목록이 필요하네" 하며 하나 붙이면, 그 순간 시뮬툴은 카메라 설정이 깨지면 같이 죽는 화면이 된다 |
| 반대로 `devices/`·`core/` 도 `src/sim/` 을 import 하지 않는다 | 양방향이어야 경계다 |
| `simRoutes` 에 `driverFor`·`deps.db`·`config.cameras` 가 없다 | 드라이버를 조립하는 순간 카메라가 없으면 시뮬툴이 통째로 못 뜬다 |
| 화면이 `/api/core/*`·`api.cameras` 를 부르지 않는다 | 같은 이유, 화면 쪽 |
| **`src/sim/**` 와 화면에 `×100` 환산이 없다** | 아래 |

### 단위를 환산하지 않는 것이 독립의 실질적 이득이다

`devices/park3d/park3dRpcClient.ts` 는 **카메라 드라이버**라, 상위 계층이 정수 raw 만 보도록
도·배율을 ×100 한다(`pan 47.1°` → `4710`). 시뮬툴은 그 계층을 지나지 않으므로
**서버가 준 값을 그대로 쓴다.**

두 곳에서 변환하면 반드시 어긋난다 — 한쪽만 고치는 날이 오기 때문이다. 그래서 규약
(오류 봉투 우선 등)은 같지만 **코드를 공유하지 않는다.**

### 프록시 규약

```
POST /api/sim/rpc  { method, params }
  · 카탈로그 밖 → 400, 서버를 두드리지도 않는다
  · RPC error 봉투를 상태코드보다 먼저 본다 (오류도 HTTP 200 으로 온다 — 실측)
  · -32601 미등록 method  → 501  "이 시뮬레이터에 그 기능이 없다"는 확정 답
  · -32000 도메인 위반    → 409  순서를 지키면 되므로 재시도가 의미 있다
  · -32602 잘못된 파라미터 → 400
  · 연결 실패             → 502 + 주소·원문
```

**서버가 준 한글 사유를 다시 쓰지 않는다.** 실측 예:
`타겟점 미설정 — measure.setTargetPoint 를 먼저 호출하세요.` — 우리가 지어낸 문장보다 정확하다.

## 3. 다섯 탭

```
/simtool
┌──────────────────────────────────────────────┐
│ 시뮬레이터 [http://192.168.0.125:13510] [연결] │  ← 탭 밖
│ ● 연결됨 · 80 method                          │
├──────────────────────────────────────────────┤
│ [프리셋 메이커][차량 배치][카메라 컨트롤][거리 측정][조명]│
├──────────────────────┬───────────────────────┤
│  (툴 패널)            │  시뮬레이터 뷰 (공용)   │
└──────────────────────┴───────────────────────┘
```

**연결 확인이 두 가지를 본다** — `system.health`(살아 있나)와 `system.catalog`(우리가 부를
메서드를 갖고 있나). 서버에 없는 것이 있으면 **그 이름을 화면이 먼저 말한다.** 눌러 본 뒤
501 을 보는 것보다 낫고, 시뮬레이터 버전이 뒤처졌을 때 무엇이 빠졌는지 바로 보인다.

### ① 프리셋 메이커 — 주차면 그룹

> **용어 충돌.** SettingManager 의 「프리셋」은 **PTZ 프리셋**(`preset_info` DB)이다.
> 여기 「프리셋」은 **주차면 그룹**이다. 화면과 코드 주석에 이 문장을 박아 뒀다.

`preset.*` 18종을 다 쓴다. 목록·상세·추가/수정/삭제/리셋·이동/회전 패드·번호 재계산·
3D 육면체 토글·저장/열기.

**파생값(각도·step폭·전체X폭·세로폭)은 계산하지 않는다.** 배치 규칙은 언리얼이 소유한다 —
`preset.get` 이 `derived` 를 실어 주면 쓰고, 안 주면 **"웹에서 계산하지 않습니다"라고
화면이 말한다.** 여기서 재현하면 규칙이 두 벌이 되고 반드시 갈린다.

### ② 차량 배치 — 23종 + 열거형

마스터가 준 카탈로그를 `web/simtoolCatalog.js` 에 담았다. **시뮬레이터 RPC 에 차종 이름
목록을 주는 메서드가 없기 때문**이다(실측 80종 어디에도 없다). `car.get` 은 `prefabId`
숫자만 준다 — 목록이 없으면 사람이 "6번이 뭐였지"를 외워야 한다.

> 서버가 목록을 주게 되면 **이 파일을 지우고 그쪽을 쓴다.** 두 벌로 두면 갈린다.

- `ECarType` 8종 — **`None = 0` 이 있다.** 0 을 "소형"으로 읽으면 한 칸씩 밀린다
- `ECarColor` 10종
- 「열기」 뒤 **prefabId ↔ 차종 대응이 미확정**이라는 사실을 토스트가 말한다
  (참조 문서 §4 의 미해결 사항) — 조용히 넘기면 다른 차종이 떴을 때 아무도 모른다

`car.list` 실측 필드가 화면과 그대로 맞는다: `carNameId`(Idx) · `presetId` · `faceSlot`(Face Id) ·
`rotY` · `prefabId` · `visible`.

**Front/Back 은 `rotY` 로 표현한다** — `car.list` 에 방향 필드가 따로 없다. 없는 필드를
지어내지 않고, 180° 근처면 Back 으로 읽는다.

### ③ 카메라 컨트롤 — 마스터 지시 반영

> pan, tilt, zoom 슬라이드 대신 상단은 컨트롤 패널을 사용하고 슬라이드 위치에 삽입한다.

**위치 슬라이더 3개는 남기고, PTZ 슬라이더 3개를 뺀 자리에 방향 패드를 넣되 그 패널
상단에 P/T/Z 현재값을 뒀다.** 별도 플로팅 창은 만들지 않았다 — 인라인으로 들어왔는데
창까지 있으면 조작 지점이 둘이 된다.

**축 이름이 스크린샷과 다르다.** 언리얼은 **Z-up** 이다(실측: `cam.list.pos.z = 13.5` 이고
`measure.cameraHeight` 도 13.5). 스크린샷의 "Camera Z 축 이동(앞뒤)"은 Unity(Y-up) 기준이라
그대로 베끼면 **사람이 높이 칸에 앞뒤 값을 넣는다.** 화면에는 `X축(좌우) · Y축(앞뒤) · 높이(Z)`.

**Min/Max 는 화면 전용**이다(마스터 확인 Q3). 시뮬레이터에 저장되지 않으므로
`cam.setLimits` 신설 대상에서 뺐다. 값이 범위 밖이면 **범위를 넓혀 값을 자르지 않는다** —
자르면 화면이 실제와 다른 위치를 보여 준다.

**상대 이동을 절대값으로 보낸다.** `cam.setPTZ` 에 속도 파라미터가 없다 — 없는 것을
지어 보내면 서버가 조용히 버려 "속도를 줬는데 왜 안 먹지"가 된다.

**위치 이동은 슬라이더에서 손을 뗄 때 한 번만** 보낸다(`change`, `input` 아님).
드래그 한 번에 수십 번 이동 명령이 나가면 시뮬레이터가 그걸 순서대로 처리하느라 밀린다.

### ④ 거리 측정 — RPC 5종 전부

기하 계산은 **전부 시뮬레이터가 한다.** 웹은 좌표를 보내고 숫자를 받아 적을 뿐이다.

- 수직각은 **양수가 내려다봄(↓)** — 부호만 보고 방향을 잘못 읽지 않게 화살표를 붙였다
- 카메라 높이는 타겟점과 무관하므로(바닥 레이캐스트) **따로 부르고, 실패해도 나머지를 막지 않는다**
- `setTargetPoint` 선행 없이 부르면 시뮬레이터의 한글 사유가 그대로 뜬다

### ⑤ 조명 설정 — **화면을 일부러 만들지 않았다**

언리얼에 `light.*` 가 없다(실측 `-32601 미등록 method: light.get`).

부를 곳이 없는 입력칸을 그려 두면 값을 넣고 「적용」을 눌러도 아무 일이 안 일어나는데
**사용자는 적용됐다고 믿는다.** 그래서 이 탭에는 조작 요소가 하나도 없고, 무엇이
필요한지와 UE 매핑만 적혀 있다. 테스트가 `<input`·`<select` 가 없음을 강제한다.

### 시뮬레이터 뷰 (5탭 공용)

**영상은 시뮬레이터에서 직접 받는다.** MJPEG 를 `<img>` 로 받는 것은 CORS 대상이 아니므로
프록시가 필요 없다 — 주소는 RPC 주소의 호스트 + `cam.list` 의 `streamPort` 로 조립한다.

**동시 스트림 슬롯 제한**(실측 `slots:1 / hardMaxSlots:2`)을 `cam.streamStatus` 로 읽어
다 찼으면 경고를 띄운다. **조용히 남의 스트림을 끊지 않는다** — 사람이 다툼을 보게 한다.

```
전체 934건 중 914 통과 · 신규 34건 전부 통과
남은 실패 20건은 Part A 이전부터 있던 것 (클린 트리에서 동일)
```

|---|---|---|---|
| 통과 | 807 | 880 | **914** |
| 실패 | 20 | 20 | **20** (동일, 전부 기존) |

`/api/sim/rpc` 는 **한 경로에 79가지 행위**가 들어 있어 가장 위험한 쪽에 맞춰
`movesCamera: true` 로 표시했다(`cam.setPTZ` 가 목록에 있다).

### 라이브 — 실제 시뮬레이터로 끝까지

`POST http://127.0.0.1:13030/api/sim/rpc` → `192.168.0.125:13510` (읽기 전용만):

```
system.health         200  {ok:true, port:13510}
cam.list              200  camId 1 · pos{x:-36.3, y:-13.6, z:13.5} · streamPort 13601
cam.getPTZ            200  {pan:47.1, tilt:30.4, zoom:2.4}     ← 도·배율 그대로
measure.cameraHeight  200  {height:13.5}
preset.list           200  []
car.list              200  carNameId·presetId·faceSlot·rotY·prefabId

measure.distance      409  타겟점 미설정 — measure.setTargetPoint 를 먼저 호출하세요.
light.get             400  허용되지 않은 시뮬레이터 메서드입니다: light.get   ← 서버를 안 두드림
cam.getPTZ(camId:99)  409  카메라 없음: camId=99
```

세 오류가 **다른 상태코드로 갈렸고**, 한글 사유가 손실 없이 통과했다.

`/simtool` 200 · JS 모듈 6개 전부 200 · `/api/settings` 가 `simTool` 을 싣는다.

### ⚠ 아직 못 한 검증

**쓰기 경로를 실서버에서 돌리지 않았다.** 프리셋 생성·차량 배치·카메라 이동은 마스터의
시뮬레이터 씬을 실제로 바꾸므로 임의로 실행하지 않았다. 화면에서 눌러 확인해 주십시오 —
읽기가 전부 통과했으므로 봉투·오류 매핑은 이미 검증됐고, 남은 것은 각 메서드의 파라미터
이름이 맞는지입니다(§7 Q 참조).

## 6. 주변 파일 영향

### 영향받는 것

| 대상 | 영향 |
|---|---|
| `/api/settings` 응답 | `simTool` 필드가 늘었다. 기존 소비자는 모르는 필드를 무시하므로 안전 |
| `config.json` | `simTool` 블록 추가. 없으면 `normalizeSimTool` 이 빈 주소로 채우고 툴이 꺼진다 |
| MCP 도구 | 에이전트가 `/api/sim/rpc` 를 부를 수 있게 됐다 — **`movesCamera:true` 라 `confirm` 없이는 거절된다** |

## 6-2. 개정 (2026-08-07 21:5x) — RPC 목록 문서 반영

마스터가 `docs/reference/unreal/20260807_173431_Park3D_RPC_메서드_목록.md` 를 제공했고,
그 문서로 **이미 만든 것에서 결함 넷을 찾아 고쳤다.**

### ① 등록 ≠ 동작 — 죽은 메서드 10개

`system.catalog` 는 **등록 여부만** 알려준다. 82개 중 10개는 호출하면 실패한다(문서 §10).
내 화면이 그중 **셋을 부르고 있었다.**

| 부르던 것 | 고친 방법 |
|---|---|
| `cam.savePreset`·`loadPreset`·`applyPreset` | 버튼을 **없앴다.** 시뮬레이터에 per-camera 프리셋 메모리가 없다 — 문서는 이것이 "웹 프리셋 이동 = PTZ만 변경" 현상의 직접 원인이라고 적고 있다 |
| `random.randomizeAll` | `car.resetRandom` 하나로 통일. `random.*` 은 절반(5개)이 죽어 있다 |
| `preset.setBoxVisible` (Use 3D) | `preset.rebuildAll {showQubeBox}` 로 교체. 문서가 "전역 3D 는 rebuildAll" 이라고 지시한다. 체크박스에 **「전역」 태그**를 붙여 면 단위가 아님을 표시 |

`SimMethod.unimplemented` 를 두어 **클라이언트가 서버를 두드리기 전에 501 + 사유**로 거절한다.
`-32000 미구현` 을 읽는 것보다 **무엇을 대신 써야 하는지**까지 알 수 있다.
테스트가 화면이 죽은 메서드를 부르지 않음을 강제한다.

### ② tilt 부호가 반대였다

문서 §3: `cam.setTilt` — **"tilt 양수가 하향"**. 내 ▲ 버튼이 `tilt + step` 이라
**카메라가 아래로 내려갔다.** tilt 축만 부호를 뒤집었다. 방향 패드가 통째로 거꾸로
동작하던 것이라 눈으로 보기 전에는 못 잡았을 결함이다.

### ③ `cam.setPosition` 파라미터 모양

문서: `camId, pos`. 나는 `{camId, x, y}` 로 평평하게 보냈다 → `{camId, pos:{x,y,z}}` 로 고쳤다.
높이(z)도 함께 실어 이동이 카메라를 바닥으로 떨어뜨리지 않게 했다.
`cam.create` 는 파라미터를 받지 않으므로 `pos` 를 빼고, 생성 후 선택까지 하도록 바꿨다.

### ④ 차량 카탈로그 정본 — `config/car_catalog.json`

마스터 확인(S4): 그 파일의 **배열 순서가 곧 `prefabId`(1부터)** 다. 화면에 하드코딩했던
23종을 지우고 서버가 `/api/sim/car-catalog` 로 그 파일을 읽어 준다. 못 읽으면
**빈 목록 + 사유**다 — 지어낸 기본값을 채우면 잘못된 이름으로 배치해 놓고 맞다고 믿는다.

`ECarType`·`ECarColor` 는 파일이 아니라 언리얼 C++ 열거형이라 화면에 남겼다.

> **S4 해소** — prefabId ↔ 차종 대응이 확정됐으므로 「열기」의 "차종이 다를 수 있습니다"
> 경고를 제거했다.

### 라이브 재확인

```
GET  /api/sim/car-catalog        200  23종, prefabId 1..23
POST /api/sim/rpc cam.applyPreset       501  "등록만 돼 있고 동작하지 않습니다 — per-camera 프리셋 메모리 없음"
POST /api/sim/rpc random.randomizeAll   501  "… 슬롯/앰비언트 통합 랜덤 백엔드 없음"
POST /api/sim/rpc preset.setBoxVisible  501  "… 전역 3D 는 preset.rebuildAll 을 쓰세요"
```

세 호출 모두 **서버를 두드리지 않고** 거절됐다.

## 6-3. 개정 (2026-08-07 23:4x) — 파일 기반 · 세 툴 같은 형태

마스터 지시 넷을 반영했다: ① `preset.list` 는 `save/3D/Preset` 의 JSON 을 참조 ②「열기」로
PC 파일을 열 것 ③ 새롭게 처음부터 시작할 수도 있을 것 ④ 모두 같은 형태로.

### ⚠ 저장 파일과 RPC 의 좌표계가 다르다 (실측)

```
Camera-1        파일 {x:-13.6, y:13.5, z:-36.3}   ↔  RPC {x:-36.3, y:-13.6, z:13.5}
차량 0-13.50.46  파일 {x:-8.167922, y:0.0220, …}   ↔  RPC {x:14.763070, y:-8.1679, …}
                          RPC(x, y, z) = 파일(z, x, y)
```

파일은 Unity(Y-up), RPC 는 언리얼(Z-up)이다. `measure.cameraHeight`(13.5)와 파일 `y`(13.5)로
교차 확인했다. **변환 없이 보내면 카메라가 땅속으로 들어가거나 맵 밖으로 날아가는데
오류로는 뜨지 않는다** — 좌표가 "그럴듯하게" 틀린다. 축을 바꾸는 자리는 `simCoords.ts`
하나이고 **서버에서만** 만진다.

### 세 툴이 같은 골격

```
[새로 만들기] [열기…] [저장…]      ← 공용 web/simtoolFileBar.js
출처 · 개수 · 저장 안 함
[목록] [추가][수정][삭제]           ← 「처음부터」를 위해 편집 가능
[시뮬로 보내기] …
```

| 탭 | 폴더 | 시뮬레이터 쪽 |
|---|---|---|
| 프리셋 메이커 | `Preset` | 보내기 · 전체 삭제 |
| 차량 배치 | `CarPos` | 보내기 · **가져오기** · 초기화 |
| 카메라 컨트롤 | `CameraPos` | **이 프리셋으로 이동** |

**브라우저는 대화상자의 시작 폴더를 지정할 수 없다**(보안 제한). 파일명 제안 · `id` 로
마지막 폴더 기억 · 표준 위치 명시 셋으로 갈음하고, 그 사실을 화면이 말한다.

### 되돌린 것

「주차면 그룹 정본을 DB 로」 결정으로 만들던 `sim_preset_group`(스키마 v7)을 되돌렸다 —
파일 형식이 이미 데이터 모델과 1:1 이라 표를 두면 정본이 셋이 된다.
**되돌릴 때 DB 파일까지 챙겨야 했다**: 코드만 v6 으로 내렸더니 떠 있던 서버가 파일에 판 7 을
기록해 둬 다음 기동이 막혔다(안전장치는 제대로 동작했다). 백업 후 `DROP TABLE` +
`PRAGMA user_version = 6` 으로 복구.

### 검증

세 종류 모두 **열기 → 저장 → 다시 열기가 원본과 동일**(preset 6 · car 65 · camera 5,
카메라는 바깥 `datas` 1 → 1 로 재묶음). 967/987 통과.

## 6-4. 정정 (2026-08-08) — main 카메라 스트림은 **있었다**

`view.*` 가 없어 지시 6(main 카메라 스트리밍)이 막혔다고 §1·§7 에 적었는데 **틀렸다.**

마스터가 알려 준 대로 시뮬레이터 메인 카메라는 `camera_info` 에 **`simulator-99`** 로
등록돼 있고 스트림이 `http://192.168.0.125:13600/stream` 으로 나온다 — **basePort** 다.
`cam.list` 는 PTZ 카메라(13601+)만 알려주므로 RPC 목록만 보면 메인 뷰가 안 보인다.
그래서 "없다"고 오판했다.

### 바뀐 것

- 영상 소스 드롭다운이 `cam.list`(RPC) → **`camera_info`(등록 카메라)** 로 바뀌었다.
  `simulator-99` 가 「시뮬레이터 메인」으로 표시되고 **기본 선택**이다.
- 영상은 `/api/stream?cameraId=` 를 지난다. 전송은 서버가 URL 스킴으로 고른다
  (rtsp→ffmpeg · http MJPEG→**ffmpeg 없이 그대로 중계** · 없으면 스냅샷 폴링).
  실카메라(rtsp)도 같은 목록에서 고를 수 있게 됐다.
- **영상은 시뮬 RPC 연결과 무관하다** — 연결이 끊겨도 나온다. 목록도 연결보다 먼저 채운다.

### 독립 경계의 유일한 예외

화면(`simtool.js`)이 `/api/cameras` 와 `/api/stream` 을 부른다. 서버 쪽 `src/sim/` 은
여전히 카메라·코어·DB 를 import 하지 않고, 툴 패널 넷도 `/api/sim/*` 뿐이다.
테스트가 이 예외를 **정확히 규정한다** — 코어(`/api/core/*`)·PTZ·DB 편집은 여전히 금지다.

`view.*` 는 여전히 필요하다. 다만 **스트리밍이 아니라 클릭 피킹** 때문이다(§7).
