# 주차면 탐색 화면 읽기 전용 카메라 뷰 추가

## 개요

2026-08-01 작업으로 `SettingMain/web/discovery.html`의 대상 카메라 카드와 `#advanced` 사이에 읽기 전용 카메라 뷰를 추가했다. 영상 카드는 고급 제어 영역 바깥에 배치되어 Hucoms에서도 선택 카메라의 영상을 확인할 수 있다. 새 서버 API나 설정 포맷은 만들지 않고 기존 `GET /api/stream`(multipart MJPEG)과 `GET /api/snapshot`(JPEG)을 재사용한다.

## 변경 클래스·함수와 로직 의도

- `SettingMain/web/discovery.html`: `#stream`, `#streamPlaceholder`, `#streamTag[aria-live="polite"]`, `#streamStart`, `#streamStop`, `#snapshotOnce`를 추가했다. 영상은 자동 시작하지 않으며 시작→정지→스냅샷 순서와 한국어 `alt`/안내 문구를 제공한다. 카드는 `#advanced`의 자손이 아니다.
- `SettingMain/web/discovery.js`:
  - `selectedCameraId`, `hasSelectedCamera`, `setStreamControls`가 현재 선택값과 카메라 목록에 따라 읽기 버튼 상태를 계산한다.
  - `startStream`은 선택 ID를 `encodeURIComponent`한 `/api/stream?cameraId=...&t=...`를 `<img>`에 연결한다. 브라우저 폴링은 만들지 않고 서버 MJPEG 연결을 소비한다.
  - `snapshotOnce`는 같은 선택 ID로 `/api/snapshot?cameraId=...&t=...`를 요청한다.
  - `stopStream`은 오류 핸들러와 `src`를 제거하고 placeholder/live 상태를 복원한다. `streamError`는 이 정리 뒤 상태 영역에 카메라 URL 또는 BackendCore 연결 확인 메시지를 표시하며 자동 재시도하지 않는다.
  - `refreshCameras`, 카메라 선택 변경 이벤트, `pagehide`에서 스트림과 discovery `poller`를 정리한다. `setCapability`의 기존 `선택 ID=활성 ID && kind=backend-core` 이중 게이트 및 고급 컨트롤 비활성화는 변경하지 않았다.
- 생산 코드 `SettingMain/src/api/server.ts`, `src/stream/frameSource.ts`, `src/clients/hucomsClient.ts`, `src/clients/backendCoreClient.ts`는 수정하지 않았다. 명시적 `cameraId` 라우팅, MJPEG abort, Hucoms/BackendCore 스냅샷 계약을 그대로 사용한다.

## 입출력 및 외부 계약

입력은 화면의 `#cameraSelect` 현재 값이다. 출력은 `<img>`의 스트림/스냅샷 JPEG와 `#streamTag` 및 전역 `#status`의 상태 문구다. 영상 함수는 `/api/cameras/active`, `/api/ptz`, `/api/discovery/*`, `/api/center*`, `/api/vla/tour`를 호출하지 않으며 활성 카메라 설정을 바꾸지 않는다. 따라서 Hucoms 활성 또는 비활성 BackendCore 후보에서도 읽기 버튼은 제공되고, 기존 고급 UI 게이트와 서버 `handleDiscovery`의 활성 BackendCore 검증(비-BackendCore 시 HTTP 409)은 그대로 유지된다.

## 영향도

- 직접 영향: `SettingMain/web/discovery.html`, `SettingMain/web/discovery.js`, 영상 정적 계약을 고정한 `SettingMain/test/server.test.ts`.
- 스타일: `SettingMain/web/app.css`는 변경하지 않고 기존 `.card`, `.viewport`, `.live`, `.row`, `.tag`, disabled 규칙을 재사용했다.
- 의존성·설정: `SettingMain/package.json`, `package-lock.json`, `tsconfig.json`, `vitest.config.ts` 및 런타임 API/설정 포맷에 변경이 없다.
- 모듈 경계: 서버의 스트림/스냅샷, `frameSource`의 RTSP·HTTP MJPEG·스냅샷 폴링 분기, Hucoms `jpeg.cgi`, BackendCore `GET /api/snapshot`을 재사용한다.
- 형제 프로젝트: `AgentVLA/ParkAgent/SettingAgent`, `ParkAgent`, `baro_calory`에는 코드·설정 변경이 없고 새 계약도 확정하지 않았다.

## 테스트 및 실제 검증 결과

QA가 `SettingMain/`에서 `npm run typecheck`, `npm run test`, `npm run build`, `git diff --check`를 실행해 모두 exit 0을 확인했다. Vitest는 9개 파일/177개 테스트 통과, 실패 0건이다. 이미 실행 중인 13030 서버를 종료하지 않고 GET만 확인했으며 `/discovery`, `/discovery.js`(8,677 bytes), `/app.css`(6,099 bytes), `/api/cameras`가 200이었다. `/api/snapshot`은 `image/jpeg`, 1,129,780 bytes를 반환했다(활성 `simulator-1`, kind `hucoms`).

인앱 브라우저가 제공되지 않아 실제 버튼 클릭, 키보드 focus, `aria-live` 낭독, 좁은 화면, 선택 변경 및 `pagehide`의 브라우저 네트워크 연결 종료는 미검증이다. 실제 MJPEG 스트림도 추가 연결을 피하기 위해 요청하지 않았다. PTZ absolute/nudge, preset goto, calibration, center/center-box, plate-home, VLA tour 등 이동 명령은 구현·검증 중 실행하지 않았다. 위 미검증 항목은 성공으로 간주하지 않는다.

## 비범위

새 영상 API·WebSocket/WebRTC/HLS, 자동 재생/자동 재연결, 다중 카메라 동시 재생, 녹화·다운로드·오버레이, BackendCore 동기화, discovery CRUD·캘리브레이션·호밍·투어 알고리즘, 인증/lease/운영 설정 변경 및 외부 SettingAgent 수정은 포함하지 않는다.
