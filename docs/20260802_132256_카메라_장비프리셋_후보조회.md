# 카메라 장비 프리셋 후보 조회

## 개요

2026-08-02 기준으로 카메라 장비의 프리셋 capability를 읽어 안전한 슬롯 후보를 수동 조회하는 변경을 기록한다. 로컬 프리셋(`PresetStore`)과 장비 capability를 별도 namespace로 유지하며, 장비의 실제 등록 목록이나 저장 이름은 조회하지 않는다.

근거 문서는 `_workspace/01_architect_plan.md`, `_workspace/02_developer_changes.md`, `_workspace/03_qa_report.md`와 현재 작업 트리의 실제 diff다. 외부 계약 근거는 `baro_calory/reference/_hucoms_extracted.txt:2845~2895` 및 `baro_calory/_forAI/memo.md:88`에 기록된 Hucoms 자료다.

## 변경 클래스·함수와 로직 의도

- `SettingMain/src/clients/cameraDriver.ts`: `DevicePresetCapability`, `DevicePresetSlot` DTO와 `CameraDriver.getDevicePresetCapability()` 계약을 추가했다.
- `SettingMain/src/clients/hucomsClient.ts`: `GET /cgi-bin/control/capabilityptz.cgi?action=getPTZ`의 `text/plain` 응답에서 대소문자 보정 없이 정확한 `PresetSupported` 키를 파싱한다. `No`는 미지원, 정수 `1~256`은 광고 최대값으로 처리하고 `min(advertised, 128)`개의 `registration: 'unknown'`, `name: null` 슬롯 후보를 합성한다.
- `SettingMain/src/clients/backendCoreClient.ts`: 장비 프리셋 인벤토리 계약이 없으므로 `501`을 명시적으로 반환한다. discovery 프리셋을 재사용하지 않는다.
- `SettingMain/src/api/server.ts`: `GET /api/device-preset-capability?cameraId=` read-only endpoint를 추가하고 카메라 통신 오류를 `502`로 매핑한다. `cameraId` 생략 시 기존 활성 카메라 규칙을 따른다.
- `SettingMain/web/api.js`, `web/control.js`, `web/index.html`, `web/app.css`: 로컬 프리셋과 분리된 장비 프리셋 카드, 수동 새로고침, 로딩·오류·미지원 상태 및 카메라 변경 시 초기화를 제공한다. 초기 진입 자동 조회·이동·goto·선택·검색은 없다.

## 입출력 및 외부 계약

Hucoms capability 요청은 정확히 `capabilityptz.cgi?action=getPTZ`이며 `preset_control.cgi`의 `set`, `gopreset`, `clearpreset` 명령은 호출하지 않는다. `PresetSupported = No`는 HTTP 200의 `supported:false`와 빈 슬롯을 뜻한다. `PresetSupported = 1~256`에서 `advertisedMaxPresetNumber`는 원값을 보존하지만 현재 제어 계약의 안전 상한은 128이므로 `usableMaxPresetNumber`와 후보 슬롯은 최대 128이다. `#N`은 후보일 뿐 등록 여부와 이름은 미확인이다.

성공 DTO는 `cameraId`, `supported`, `advertisedMaxPresetNumber`, `usableMaxPresetNumber`, `listing: "unsupported"`, `naming: "unsupported"`, `slots`를 포함한다. 지원하지 않는 장비는 광고·사용 최대값 0과 빈 배열을 반환한다. 키 누락·빈 값·0·음수·257 이상·비정수·대체 키는 계약 오류다. 실제 목록/이름 endpoint는 미구현이며 BackendCore에서는 `501`이다. 사용자명·비밀번호는 Hucoms client 내부 URL 구성에만 존재하고 응답·UI·오류에는 노출하지 않는다.

## 영향도

- 직접 영향: `SettingMain/src/clients/cameraDriver.ts`, `hucomsClient.ts`, `backendCoreClient.ts`, `api/server.ts`, `web/api.js`, `web/control.js`, `web/index.html`, `web/app.css`.
- 테스트 및 공유 타입 영향: `SettingMain/test/hucomsClient.test.ts`, `test/server.test.ts`, `test/settle.test.ts`; 모든 CameraDriver mock/구현체가 새 capability 메서드를 만족해야 한다.
- 의존성·설정 포맷: package 의존성, `SettingMain/config/config.json`, `config.example.json`은 변경하지 않았다.
- 로컬 기능 경계: 기존 `/api/presets` CRUD, PTZ, 로컬 저장·이동 동작은 유지한다. 장비 후보 조회는 읽기 전용이며 자동 polling/동기화가 없다.
- 형제 SettingAgent: `AgentVLA/ParkAgent/SettingAgent` 경로에는 변경이 없고 신규 namespace를 소비하지 않는 한 파급이 없다. 형제의 Hucoms 계약은 조사 범위 밖이므로 추측하지 않는다.
- 비범위: 장비 프리셋 등록·수정·삭제·이동, 실제 등록 여부 탐지, 장비 이름 조회, 로컬 프리셋 복제, 후보 선택·검색, 미확인 CGI 역공학.

## 테스트 및 실제 검증

QA 결과는 `npm run typecheck` 통과, `npm run test` 9개 파일/199 테스트 통과, `npm run build` 통과, `git diff --check` 통과다. 자동 fixture는 `No`, `1`, `128`, `129`, `256` 및 잘못된 capability를 검증했고 129/256에서도 #128까지만 노출됨을 확인했다. PTZ, `set/gopreset/clear`, 저장·삭제·이동 명령은 실행하지 않았다.

기존 13030 서버(PID 33520)는 유지한 채 active `real-camera-1`에 허용된 1회 `GET /api/device-preset-capability?cameraId=real-camera-1`을 수행했으며 HTTP `502`, `카메라 통신 실패: fetch failed`가 반환됐다. 따라서 실장비의 실제 `PresetSupported` 응답은 미확인이고 mock 계약으로만 검증됐다. 브라우저 직접 검증도 수행하지 않아 성공으로 표현하지 않는다.
