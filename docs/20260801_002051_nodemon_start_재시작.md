# nodemon 기반 `npm start` 재시작 적용

## 개요

`SettingMain`의 `npm start`가 기존 단발 실행(`tsx src/index.ts`)에서 로컬
`nodemon` 감시 실행으로 바뀌었다. `src` 아래 TypeScript 파일만 감시하며 변경 시
동일한 `tsx src/index.ts` 자식 프로세스를 재시작한다. 이번 변경은 개발 실행 계약에
한정되고 서버·도메인·설정 저장 코드나 형제 SettingAgent 코드는 수정하지 않았다.

## 변경 클래스·함수와 로직 의도

- TypeScript 클래스·런타임 함수의 변경은 없다. 기존 진입점
  `SettingMain/src/index.ts`와 서버 구현은 그대로 실행된다.
- `SettingMain/package.json`의 `scripts.start`를
  `nodemon --watch src --ext ts --exec "tsx src/index.ts"`로 변경했다. 감시 범위를
  `src/**/*.ts`로 제한해 `config/config.json` 저장이나 정적 `web/` 파일 변경이
  의도하지 않은 재시작을 일으키지 않도록 했다. 기존 `dev` 스크립트는 유지했다.
- `SettingMain/package.json`의 `devDependencies`에 `nodemon ^3.1.14`를 추가하고
  `SettingMain/package-lock.json`에 nodemon과 chokidar 등 전이 의존성을 잠갔다.
- `SettingMain/test/packageScripts.test.ts`의 `isUnknownRecord`, `isStringRecord`,
  `readPackageManifest` 함수가 JSON 입력을 런타임 타입 가드로 확인하고, `package
  scripts` 테스트 케이스가 파일 기준으로 `SettingMain/package.json`을 읽어 nodemon
  위치와 정확한 start 명령을 검증한다. 외부 프로세스·네트워크는 시작하지 않는다.

## 입출력 및 외부 계약

입력은 `SettingMain`의 npm manifest와 `src` 내 `.ts` 파일 변경이다. nodemon은
`tsx src/index.ts`를 실행하고 기존 HTTP 서버 계약(기본 포트 13030, host
`0.0.0.0`)을 그대로 사용한다. `/api/health`의 응답 형식이나 SettingAgent REST/
도메인 식별자 계약은 변경하지 않았다. 운영 설치에서 devDependency를 제외하면
nodemon을 찾을 수 없으므로 본 `start` 명령은 개발 의존성 설치 환경을 전제로 한다.

## 영향도

| 경로 | 영향 |
|---|---|
| `SettingMain/package.json` | start 실행 방식과 개발 의존성 변경 |
| `SettingMain/package-lock.json` | nodemon 3.1.14 및 전이 의존성 잠금 |
| `SettingMain/test/packageScripts.test.ts` | package 실행 계약 단위 테스트 추가 |
| `SettingMain/src/index.ts` | 코드 변경 없음; nodemon이 계속 실행하는 진입점 |
| `SettingMain/src/config/configStore.ts` | 코드 변경 없음; JSON 저장 때문에 ts 감시 제한의 근거 |
| `SettingMain/src/api/server.ts` | 코드 변경 없음; `/api/health` 기존 소비자 계약 유지 |
| `SettingMain/tsconfig.json`, `SettingMain/vitest.config.ts` | 변경 없음; 기존 ESM/typecheck 및 테스트 포함 규칙 유지 |
| 저장소 루트 `package.json` 및 별도 `node_modules` | 기존 사용자 상태 보존, 이번 변경에서 수정하지 않음 |
| `AgentVLA/ParkAgent/SettingAgent` 등 형제 프로젝트 | 코드·설정·연동 계약 변경 없음 |

런타임 모듈 의존성은 늘지 않았고 nodemon은 개발 의존성으로만 추가됐다. npm 설치 시
audit 취약점(3 moderate, 1 high, 1 critical)이 보고됐으나 이번 실행 계약 범위에서
자동 수정하지 않았다.

## 테스트 및 실제 검증 결과

- `npm ls nodemon --depth=0`: `settingmanager@0.1.0` 아래 `nodemon@3.1.14` 확인.
- `npm run typecheck`, `npm run build`, `git diff --check`: 통과(단 diff check는
  `package.json` LF→CRLF 경고만 보고).
- `npm run test`: **9개 파일, 163개 테스트 통과, skipped 0**.
- 실제 `npm start` 로그에서 nodemon 3.1.14, `src\\**\\*` 감시, `ts` 확장자,
  `tsx src/index.ts` 실행을 확인했다. `src/index.ts`의 내용은 바꾸지 않고 mtime만
  갱신했을 때 `restarting due to changes...`와 재시작 로그가 관찰됐다.
- 포트 13030은 기존 PID 23196이 점유했다. QA 프로세스는 `EADDRINUSE`로 listen하지
  못했으므로 `/api/health`의 200 응답은 기존 프로세스에서 온 것이며 **QA 인스턴스의
  health 성공으로 검증하지 않았다**. 포트 충돌 해소 후 동일 명령을 재실행해야 한다.
- QA가 시작한 PID만 종료했고 기존 PID 23196은 종료하지 않았다. 소스 SHA-256은
  mtime 전후 동일하고 원래 mtime을 복원했다.
