# 주차면 탐색 카메라 제어형 레이아웃 변경 문서

## 개요

2026-08-01 11:41:58 (Asia/Seoul) 기준으로 주차면 탐색 화면의 정보구조를 카메라 제어 화면의 원칙에 맞춰 재배치했다. 목표는 마스터 스크린샷의 픽셀을 복제하는 것이 아니라, 좌측 대상 선택·탐색 조작과 우측 넓은 영상이라는 구조를 재사용하는 것이다. 데스크톱(1100px 초과)에서는 영상 열이 우측에 남고 sticky로 유지되며, 1100px 이하에서는 대상 → 영상 → 고급 조작의 한 열로 바뀐다.

## 변경 클래스·함수와 로직 의도

- `SettingMain/web/discovery.html`
  - `.layout.discovery-layout` 아래 direct child를 정확히 `#discoveryTarget` → `#discoveryViewer` → `#advanced` 순서로 구성했다.
  - 대상 카드에는 기존 `#cameraSelect`, `#activateCamera`, `#capability`, `#cameraNote`를 보존했다.
  - 영상 영역은 `aside#discoveryViewer` 안의 카드로 두고 `#streamTag`, `#stream`, `#streamPlaceholder`, `#streamStart`, `#streamStop`, `#snapshotOnce`를 유지했다. 버튼은 viewport 아래 `.body.discovery-stream-actions`에 두며 `type="button"`, `aria-controls="stream"`을 사용한다.
  - `#advanced` 내부 카드 순서는 탐색 프리셋 → 주차면 점 → 자동 작업이다. `#centerBox`는 x/y만 저장하는 discovery point 계약에 따라 disabled와 미지원 안내를 유지한다. `#status`는 status/live-region ARIA를 명시했다.
- `SettingMain/web/app.css`
  - `.discovery-layout`에 `minmax(320px, 420px) minmax(0, 1fr)` 및 `target/viewer`, `advanced/viewer` grid area를 추가했다. `#discoveryViewer`, `#advanced`에는 `min-width: 0`을 적용했다.
  - 1101px 이상에서만 `#discoveryViewer { position: sticky; top: 72px; }`를 사용한다. `position: fixed`나 overlay, 별도 내부 스크롤은 없다.
  - 1100px 이하에서는 1열 area와 `position: static`으로 전환한다. 영상 제어 행은 `.discovery-stream-actions .row`에서 우측 정렬된다. 기존 16:9 viewport와 `object-fit: contain` 규칙은 재사용한다.
- `SettingMain/test/server.test.ts`
  - HTML direct-child 순서, 기존 ID 단일 존재, 버튼/ARIA 속성, CSS grid·sticky·모바일 breakpoint를 정적 회귀 테스트로 고정했다.
  - BackendCore 이중 gate, Hucoms 409, `center-box` 501, capability 422 및 스트림 lifecycle ID 소비 계약을 함께 검증한다.

기존 `SettingMain/web/discovery.js`의 스트림 lifecycle(시작 전 정리, cache-busting URL, 오류·선택 변경·refresh/pagehide 시 `src`/poller 해제)와 ID 기반 연결은 변경하지 않았다. 읽기 영상은 선택한 카메라 ID의 `/api/stream?cameraId=...` 및 `/api/snapshot?cameraId=...`를 재사용하며, 화면 진입만으로 자동 재생·재연결하지 않는다.

## 입출력 및 외부 계약

- 클라이언트 고급 조작은 선택 카메라가 활성 ID와 같고 `kind === 'backend-core'`일 때만 활성화된다. Hucoms 또는 활성 불일치 상태에서는 `#advanced`를 숨기지 않고 native 입력·버튼을 disabled로 표시한다.
- `SettingMain/src/api/server.ts`의 discovery gate는 비-BackendCore 활성 카메라에 409를 반환한다. discovery point는 x/y만 저장하므로 `/api/center-box`는 501을 보존한다. BackendCore capability 오류 422와 외부 409도 전달한다. VLA tour 요청은 `saveSpots:false` 계약을 유지한다.
- 활성 카메라 변경, PTZ, preset goto, center, calibration, plate-home, tour는 레이아웃 변경으로 호출하지 않는다. 실제 QA에서도 해당 명령과 POST 제어를 실행하지 않았다.
- 새 API, DTO, 설정 포맷, 인증/lease 계약, 런타임 의존성은 추가하지 않았다.

## 영향도

직접 영향 파일은 `SettingMain/web/discovery.html`, `SettingMain/web/app.css`, `SettingMain/test/server.test.ts`다. 소비자/생산자 경계는 `SettingMain/web/discovery.js`(DOM ID·스트림 수명주기), `SettingMain/src/api/server.ts`(선택 카메라 라우팅·BackendCore 409·center-box 501), `SettingMain/src/clients/backendCoreClient.ts` 및 `SettingMain/src/stream/*`(오류·영상 읽기)다. 비교 기준인 `SettingMain/web/index.html`·`control.js`의 카메라 제어 레이아웃은 수정하지 않았다.

`SettingMain/package.json`, `package-lock.json`, `tsconfig.json`, `vitest.config.ts`, API/DTO·config와 형제 `AgentVLA/ParkAgent/SettingAgent`, BackendCore 및 카메라/시뮬레이터 코드는 변경 대상이 아니다. 따라서 형제 SettingAgent에는 새 호출·타입·설정 전파가 없고, 기존 HTTP 계약을 소비하는 경우에만 동일한 409/501/422 경계가 적용된다. 픽셀 단위 시각 복제, 새 디자인 시스템, 스트림 프로토콜, discovery CRUD/알고리즘, 실제 운영 카메라 제어는 비범위다.

## 테스트 결과와 검증 한계

QA 보고서 기준 `npm run typecheck` 통과, `npm run test` 9개 파일·178/178 테스트 통과, `npm run build` 통과, 저장소 루트 `git diff --check` 통과(exit 0; CRLF 변환 경고만 있음)다. 기존 13030 리스너를 유지한 채 `/discovery`, `/app.css`, `/api/cameras` GET만 수행했으며 활성 카메라는 Hucoms `simulator-1`이고 BackendCore 장비는 없었다.

인앱 브라우저 부재로 1440/1100/768/390px 폭, 200% 확대, sticky 스크롤, 키보드 focus/overflow를 실제 렌더링으로 검증하지 못했다. PTZ·preset goto·center·calibration·home·tour 및 활성 카메라 변경, `/api/stream`·`/api/snapshot` 호출도 실행하지 않았다. 위 항목은 성공으로 간주하지 않고 미검증으로 남긴다.
