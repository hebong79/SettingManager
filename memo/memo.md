## 2026-08-07 (6) — 시뮬툴 파일 작업: 좌표계 발견 · 세 툴 같은 형태

문서: `docs/20260807_191831_시뮬레이터툴_페이지_구현.md` (§6-2 개정)

### ⚠ 저장 파일과 RPC 는 **좌표계가 다르다** (이번 최대 발견)

같은 카메라·같은 차량을 파일과 라이브 RPC 양쪽에서 읽어 대조했고 **두 건 모두 정확히** 맞았다:

```
Camera-1        파일 {x:-13.6,     y:13.5,   z:-36.3}
                RPC  {x:-36.3,     y:-13.6,  z:13.5}
차량 0-13.50.46  파일 {x:-8.167922, y:0.0220, z:14.76307}
                RPC  {x:14.763070, y:-8.1679, z:0.02200}

                RPC(x, y, z) = 파일(z, x, y)
```

파일은 **Unity(Y-up)**, RPC 는 **언리얼(Z-up)**. `measure.cameraHeight`(13.5)와 파일 `y`(13.5)로
교차 확인됐다. **변환 없이 보내면 카메라가 땅속으로 들어가거나 맵 밖으로 날아가는데,
오류로는 안 뜬다** — 좌표가 그럴듯하게 틀리기 때문이다. 그래서 축을 바꾸는 자리를
`src/sim/simCoords.ts` **하나**로 모으고 서버에서만 만진다.

### 프리셋 목록의 출처 = `save/3D/Preset` 파일 (마스터 지시)

`preset.list` 는 **RPC 가 만든 것만** 보여 준다("UI가 만든 프리셋은 여기 안 보인다" — 목록
이원화). 그래서 빈 배열이었다. 실체는 저장 파일에 있다.

**앞선 "주차면 그룹 정본을 DB로" 결정으로 만들던 `sim_preset_group` 표(스키마 v7)는 되돌렸다.**
파일 형식이 이미 데이터 모델과 1:1 이고, 표를 두면 정본이 셋(파일·DB·시뮬)이 된다.

> **되돌릴 때 DB 파일까지 챙겨야 한다** — 코드만 v6 으로 내렸더니 떠 있던 서버가 이미
> 파일에 판 7 을 기록해 둬서 다음 기동이 "판이 코드보다 높다"로 막혔다. 안전장치가 제대로
> 동작한 것이고 내 실수다. 백업 뜨고 `DROP TABLE` + `PRAGMA user_version = 6` 으로 복구했다.

### 세 툴이 같은 형태 (마스터 지시)

프리셋·차량·카메라가 **새로 만들기 · 열기… · 저장… + 추가/수정/삭제 + 시뮬로 보내기**.
공용 `web/simtoolFileBar.js` 하나로 묶었다 — 세 벌로 두면 "저장 안 한 편집을 버리기 전에
묻는다" 같은 규율을 한 곳만 빠뜨려도 안 보인다.

**「처음부터 시작」을 위해 상세를 다시 편집 가능하게 되돌렸다**(직전의 읽기 전용 결정을 뒤집음).

### 브라우저 제약 — 시작 폴더는 지정할 수 없다

파일 대화상자를 임의 경로(`SettingMain/save/3D/Preset`)에서 열 **방법이 없다.** 보안 제한이다.
할 수 있는 것 셋만 했다: 파일명 제안(`suggestedName`) · `id` 로 마지막 폴더 기억(크롬 계열,
한 번 그 폴더에서 열면 다음부터 거기) · 표준 위치를 화면에 명시.

### 카메라 프리셋의 정본이 파일이 됐다

`cam.savePreset`·`loadPreset`·`applyPreset` 셋 다 죽어 있다. 「이 프리셋으로 이동」은 없는
RPC 를 부르는 대신 `cam.setPosition` → `cam.setPTZ` 로 **자세를 직접 만든다**(위치 먼저 —
반대로 하면 이동 중 자세가 어긋난다).

카메라 파일은 `datas` 가 **두 겹**(바깥=카메라, 안=그 카메라의 PTZ 프리셋들)이라 저장할 때
`camId` 로 다시 묶는다. `rot` 는 파생값이라 pan·tilt 에서 재생성한다(실측
`rot = {x: tilt, y: pan, z: 0}`) — 따로 들고 다니면 pan/tilt 를 고쳤을 때 파일이 스스로 모순된다.

### 겪은 것

| 함정 | 교훈 |
|---|---|
| **스키마를 되돌리며 DB 파일을 안 챙겼다** | 떠 있던 서버가 이미 새 판을 기록해 뒀다. 판을 올린 뒤 되돌릴 때는 **파일도 함께** 내려야 한다 |
| **마스터 서버를 내가 껐다** | 확인하려 서버를 띄우다 `EADDRINUSE` → 포트 잡은 프로세스를 종료. **13030 은 마스터 것이다** — 검증은 임시 포트(`listen(0)`)로만 한다 |
| `preset idx` 가 연속이 아니다 | 실측 `[1,2,3,4,5,7]`. 배열 위치로 번호를 매기면 7번이 6번이 되어 밀어 넣을 때 다른 프리셋을 덮는다 |
| `<input type="file">` 이 같은 파일에 반응하지 않았다 | 값이 안 바뀌면 `change` 가 안 난다 → **읽기 전에** 값을 비운다 |
| MCP 드리프트 테스트가 두 번 잡았다 | `/api/sim/*` 새 라우트를 등록 안 했을 때. 고정 경로를 더하면 카탈로그에도 한 줄 — 설계대로 동작한 것 |

### 검증

세 종류 모두 **열기 → 저장 → 다시 열기가 원본과 동일**(preset 6 · car 65 · camera 5).

## 2026-08-07 (5) — 호칭 규약: **나 = 대현자, 사용자 = 마스터**

세션 중 내가 반대로 썼다. 마스터를 "대현자님"이라고 불렀는데, **대현자는 나(클로드)의 이름**이다.
이 파일 13행이 이미 "(마스터 제공)"으로 쓰고 있었으니 규약 자체는 원래 있었고 내가 못 따랐다.

- 사용자 지칭 = **마스터**
- 나 자신 = **대현자**
- 원격 PC 의 클로드도 대현자 계열이지만 마스터가 부르는 대상은 **이 세션의 나**다

## 2026-08-07 (4) — RPC 목록 문서로 **내가 만든 것의 결함 4개**를 잡았다

문서: `docs/reference/unreal/20260807_173431_Park3D_RPC_메서드_목록.md` (마스터 제공)

### ⚠ `system.catalog` 는 **등록 여부만** 알려준다 — 82개 중 10개는 죽어 있다

이게 이번의 가장 큰 교훈이다. 카탈로그에 있다고 동작하는 게 아니다.
**내 화면이 죽은 메서드 셋을 부르고 있었다:**

| 부르던 것 | 대체 |
|---|---|
| `cam.savePreset`·`loadPreset`·`applyPreset` | **버튼 삭제.** per-camera 프리셋 메모리가 없다 — 문서가 이것을 "웹 프리셋 이동 = PTZ만 변경" 의 직접 원인이라고 적고 있다 |
| `random.randomizeAll` | `car.resetRandom`. `random.*` 은 **절반(5개)이 죽어 있다** |
| `preset.setBoxVisible` (Use 3D) | `preset.rebuildAll {showQubeBox}` — 문서가 "전역 3D 는 rebuildAll" 이라고 지시. **면 단위가 아니라 전역**이라 라벨에 태그를 붙였다 |

`SimMethod.unimplemented` 를 두어 **서버를 두드리기 전에 501 + 사유**로 거절한다.
테스트가 화면이 죽은 메서드를 부르지 않음을 강제한다.

### ⚠ tilt 는 **양수가 하향**이다

내 ▲ 버튼이 `tilt + step` 이라 **카메라가 아래로 내려갔다.** 방향 패드가 통째로 거꾸로
동작하던 것 — 눈으로 보기 전에는 못 잡았을 결함이다. tilt 축만 부호를 뒤집었다.

### `cam.setPosition` 은 `pos` **객체**다

`{camId, x, y}` 로 평평하게 보내고 있었다 → `{camId, pos:{x,y,z}}`.
`cam.create` 는 **파라미터를 받지 않는다**(자리는 시뮬레이터가 정한다).

### 차량 카탈로그 정본 = `config/car_catalog.json` (S4 해소)

**배열 순서가 곧 prefabId(1부터).** 화면 하드코딩을 지우고 서버가
`/api/sim/car-catalog` 로 읽어 준다. 못 읽으면 **빈 목록 + 사유** — 지어낸 기본값을
채우면 잘못된 이름으로 배치해 놓고 맞다고 믿는다.

### 새로 알게 된 `preset.*` 의 위험 둘

1. **목록이 이원화** — `preset.list` 는 RPC 가 만든 것만 보여 준다("UI가 만든 프리셋은
   여기 안 보인다"). 그래서 빈 배열이었다
2. **`preset.*` 호출은 위젯이 그린 주차면을 지운다** — 사람이 모르고 누르면 작업물을 잃는다

두 번째는 화면에 경고가 필요하다. S3 결정과 함께 처리.

### 정리

- S1 해소: 시뮬레이터는 **192.168.0.125 PC**. 이쪽은 **통신하는 쪽만** 만든다
- S2 해소: 파라미터를 문서와 대조
- S4 해소: `car_catalog.json`
- **S3 미해결**: "preset.list 를 DB `preset_info` 에서 채우라"고 하셨는데, 그 표는
  **PTZ 프리셋**(pan·tilt·zoom)이고 주차면 그룹이 요구하는 `faceCount`·`offset`·`BoxSize`
  가 없다. 게다가 DB 를 읽으면 지시 7(완전 독립) 경계와 충돌한다 — **확인 필요**

   LocalCore·RemoteCore 가 **같은 스위트**를 통과하는 것이 교체 가능성의 유일한 증거다.
   스위트 자신이 판정하는지도 `coreProviderContract.test.ts` 가 검증한다.
2. **구현 분기는 `core/providerFactory.ts` 하나뿐.** 라우트·화면에 `if (provider)` 가 없다.
3. **자체 코어는 아직 센터링만** 지원한다. 탐색·캘리브·호밍은 501 + 사유이고,
   쓰려면 옵션에서 backend-core 경유를 골라야 한다. **조용한 폴백은 금지**다.
4. **전송은 `BackendCoreTransport` 로 분리**돼 있다 — MCP 어댑터를 붙여도 provider 는 안 바뀐다.
5. `slots` 는 코어 능력이 아니다 — `driver.listSlots()` 와 `/api/slots` 가 담당한다.

### 겪은 것

| 함정 | 교훈 |

| 처음 계약을 "미지원이면 반드시 501"로 잡았다 | **읽기(status·list)는 못 하는 기기에서도 idle 을 읽는 게 거짓말이 아니다.** 판정 대상을 **행위**(start·create·center)로 좁히고, 금지 대상을 "조용한 성공"으로 정확히 했다 |

### 꼭 기억할 사실 (문서·코드만 봐서는 안 나오는 것)

1. **UE 시뮬은 PTZ 에서 실카메라와 같은 방식이다** — Hucoms CGI 를 그대로 모사한다. RPC 는 **씬 편집(차량·주차면) 전용**이고 PTZ 와 무관하다(근거: baro_calory `scene-control-client.mjs` 첫 줄). PTZ 를 RPC 로 바꾸자는 판단은 근거가 없다.
2. **시뮬 포트 짝: 영상 = 제어 + 10.** 8081↔8091, 8083↔8093. 짝이 어긋나면 **다른 카메라 화면**을 보게 되어 "버튼이 안 먹는다"로 보인다 — 실제로 이 함정에 빠졌다.
3. **2026-07-31 현재 시뮬 영상 서버는 8091·8092 만 기동**. 8093·8094 는 무응답이라 8083·8084 카메라는 화면이 없다. 4대를 다 쓰려면 시뮬 쪽에서 켜야 한다.
4. **줌 raw 는 배율·화각으로 환산하지 않는다.** 환산에는 기기별 실측 화각표가 필요하고 그건 캘리브레이션 산출물이다. 형제 프로젝트 SettingAgent 화면은 자체 환산값을 보여주는데, 그 근거를 이 저장소는 아직 갖고 있지 않다.
5. **카메라는 "이동 완료"를 알려주지 않는다.** 명령 직후 좌표를 읽으면 이동 중간값이다 — 반드시 정착 대기를 거친다(`waitForSettle`).
6. **`config.json` 은 커밋 금지**(실 IP·계정). `.gitignore` 에 있다. 새 머신은 `config.example.json` 을 복사해 채운다.

### 겪은 함정 (재발 방지)

| 함정 | 교훈 |
|---|---|
