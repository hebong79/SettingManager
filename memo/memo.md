## 2026-08-03 — 구조 정리 완료 (M1~M7): 단일 제어면 + 코어 포트

### 무엇이 바뀌었나

**같은 일(센터링)을 하는 경로가 셋이었고 화면이 체크박스로 골랐다.** 이걸 하나로 합쳤다.

- `/api/core/*` 단일 제어면. 옛 경로 9종 삭제(404): `/api/discovery/*` · `/api/center` ·
  `/api/center-box` · `/api/ptz/center` · `/api/independent-core/*` · `?useBackendCore=1`
- 구현 선택은 **설정** `core.provider` (기본 **local**). 질의 파라미터가 아니다
- `clients/`→`devices/`, `stream/`→`media/`, `server.ts` 542→74줄 + `api/routes/` 분할
- 테스트 239 → **280**

### 꼭 기억할 것

1. **계약의 정본은 타입이 아니라 적합성 스위트**다(`test/coreProviderConformance.ts`).
   LocalCore·RemoteCore 가 **같은 스위트**를 통과하는 것이 교체 가능성의 유일한 증거다.
   스위트 자신이 판정하는지도 `coreProviderContract.test.ts` 가 검증한다.
2. **구현 분기는 `core/providerFactory.ts` 하나뿐.** 라우트·화면에 `if (provider)` 가 없다.
3. **자체 코어는 아직 센터링만** 지원한다. 탐색·캘리브·호밍은 501 + 사유이고,
   쓰려면 옵션에서 backend-core 경유를 골라야 한다. **조용한 폴백은 금지**다.
4. **전송은 `BackendCoreTransport` 로 분리**돼 있다 — MCP 어댑터를 붙여도 provider 는 안 바뀐다.
5. `slots` 는 코어 능력이 아니다 — `driver.listSlots()` 와 `/api/slots` 가 담당한다.

### 겪은 것

| 함정 | 교훈 |
|---|---|
| 처음 계약을 "미지원이면 반드시 501"로 잡았다 | **읽기(status·list)는 못 하는 기기에서도 idle 을 읽는 게 거짓말이 아니다.** 판정 대상을 **행위**(start·create·center)로 좁히고, 금지 대상을 "조용한 성공"으로 정확히 했다 |
| 적합성 스위트가 내 RemoteCore 구현의 결함 2건을 잡았다 | 미지원 능력을 그대로 원격에 흘려보내 조용히 성공하던 경로 · 오류에 엉뚱한 능력 이름 |
| M1(순수 이동) 중 `driverFactory` 의 형제 import 가 깨졌다 | typecheck 가 즉시 잡았다. **이동과 기능 변경을 섞지 않은 판단이 값을 했다** |

## 2026-07-31 — 1차 구축 완료 (설계 → 구현 → 시뮬 연동)

### 지금 어디까지 와 있나

**동작하는 것**: TypeScript(Node ESM) 서비스 `SettingMain/` + 웹 콘솔 2페이지(카메라 제어 / 옵션).
실카메라(Hucoms CGI)와 UE 시뮬레이터 양쪽에서 **PTZ 제어·영상·프리셋·주차면 조회가 실기로 검증됨**.
런타임 npm 의존성 0개(`node:http`), 외부 프로세스는 `ffmpeg` 하나.

- 실행: `cd SettingMain && npm start` → <http://127.0.0.1:13030/> (현재 `0.0.0.0` 바인드, LAN 은 `192.168.0.10:13030`)
- 테스트: `npm run test` → **162/162 통과**
- 문서: `docs/` 3건 (설계서 · 1차 구현 · 시뮬 연동/결함수정)

### 꼭 기억할 사실 (문서·코드만 봐서는 안 나오는 것)

1. **UE 시뮬은 PTZ 에서 실카메라와 같은 방식이다** — Hucoms CGI 를 그대로 모사한다. RPC 는 **씬 편집(차량·주차면) 전용**이고 PTZ 와 무관하다(근거: baro_calory `scene-control-client.mjs` 첫 줄). PTZ 를 RPC 로 바꾸자는 판단은 근거가 없다.
2. **시뮬 포트 짝: 영상 = 제어 + 10.** 8081↔8091, 8083↔8093. 짝이 어긋나면 **다른 카메라 화면**을 보게 되어 "버튼이 안 먹는다"로 보인다 — 실제로 이 함정에 빠졌다.
3. **2026-07-31 현재 시뮬 영상 서버는 8091·8092 만 기동**. 8093·8094 는 무응답이라 8083·8084 카메라는 화면이 없다. 4대를 다 쓰려면 시뮬 쪽에서 켜야 한다.
4. **줌 raw 는 배율·화각으로 환산하지 않는다.** 환산에는 기기별 실측 화각표가 필요하고 그건 캘리브레이션 산출물이다. 형제 프로젝트 SettingAgent 화면은 자체 환산값을 보여주는데, 그 근거를 이 저장소는 아직 갖고 있지 않다.
5. **카메라는 "이동 완료"를 알려주지 않는다.** 명령 직후 좌표를 읽으면 이동 중간값이다 — 반드시 정착 대기를 거친다(`waitForSettle`).
6. **`config.json` 은 커밋 금지**(실 IP·계정). `.gitignore` 에 있다. 새 머신은 `config.example.json` 을 복사해 채운다.

### 겪은 함정 (재발 방지)

| 함정 | 교훈 |
|---|---|
| 필드 개명(`rtspUrl`→`streamUrl`) 시 별칭을 **읽기에만** 달았다 | 갱신 경로에도 달아야 한다. 안 그러면 옛 화면의 입력이 **조용히 버려진다** |
| 서버를 고쳐도 브라우저가 옛 화면을 들고 있었다 | 정적 파일은 `no-store`. 증상이 "저장했는데 안 바뀐다"로 나타나 원인 짚기가 어렵다 |
| Git Bash(CP949)에서 `curl -d '{"label":"한글"}'` 로 테스트 | 한글이 U+FFFD 로 깨진 채 설정에 저장됐다. **검증 명령이 데이터를 오염시켰다.** 지금은 서버가 400 으로 거부한다. 한글을 보낼 땐 UTF-8 파일로 `--data-binary @file` |
| 백그라운드 서버 정리에 `Stop-Process node` 를 광범위하게 썼다 | 사용자의 다른 node 프로세스까지 죽였다. **포트로 특정**해서 죽일 것: `Get-NetTCPConnection -LocalPort 13030 -State Listen` |
| "통신이 안 된다"는 신고 | 실제로는 통신 정상 + 화면 불일치였다. **증상을 그대로 믿지 말고 축별·경로별로 실측**할 것 |

### 사용자 결정 사항

- **mint(발행) 는 기본 false + 명시 승인** — `config.json` 을 덮어쓰고 git 에 문서를 남기는 동작이라 보수적으로 잡았다.
- **실카메라 PTZ 이동 명령은 미실행** — 운영 중인 물리 카메라라 별도 승인이 필요하다고 판단. 읽기(PTZ·스냅샷·스트림)만 검증했다.
- **서버 바인드 `0.0.0.0`** — 다른 PC 접속 요청으로 변경(2026-07-31). 방화벽 인바운드 규칙은 사용자가 직접 추가(관리자 권한 필요). **인증이 없으므로 사내망 전용.**
- **옵션 페이지는 한쪽 컬럼만** 사용(660px). 카메라 제어 페이지는 영상 때문에 넓게 유지.
- **장비 내장 프리셋(1~255) 은 넣지 않음** — 자체 프리셋과 섞으면 정본이 모호해진다.
