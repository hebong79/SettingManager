시뮬레이터 확인 중

주소를 확인하고 「연결 확인」을 누르세요.

이 주소는 카메라 코어(backend-core)와 다른 것입니다 — 여기는 씬을 편집하는 시뮬레이터 자신의 JSON-RPC 입니다. 시뮬레이터 툴은 카메라 설정·DB 를 전혀 쓰지 않습니다.

⚠ 이 탭의 쓰기 동작은 시뮬레이터 UI 로 그린 주차면을 지웁니다. 시뮬레이터는 위젯 목록과 RPC 목록을 따로 갖고 있어서, preset.* 를 호출하면 위젯이 그려 둔 것이 사라집니다. 읽기(목록·상세)는 안전하고, 「시뮬로 보내기」와 「전체 삭제」만 위험합니다.

주차면 프리셋 -

여기 「프리셋」은 주차면 그룹(N개 면의 배치 단위)입니다 — 카메라 제어의 PTZ 프리셋과 다른 것입니다. 목록은 save/3D/Preset 의 저장 파일에서 옵니다 — 시뮬레이터의 preset.list 는 RPC 가 만든 것만 보여 주므로 사람이 그린 배치가 거기 안 보입니다.

「시뮬로 보내기」는 preset.clear 뒤 파일의 프리셋을 하나씩 preset.create 로 넣습니다 — 시뮬레이터의 기존 주차면이 전부 사라집니다.

상세

-

좌표는 RPC 계(언리얼 Z-up)로 보여 줍니다 — 저장 파일은 Unity(Y-up)라 서버가 RPC(x,y,z) = 파일(z,x,y) 로 바꿔 읽습니다(실측 검증). 상세는 읽기 전용입니다: 편집은 시뮬레이터 UI 나 저장 파일에서 합니다.

프리셋 이동

언리얼은 Z-up 입니다 — 평면이 X·Y 이고 높이가 Z 입니다. 회전 모드에서는 ◀▶ 가 Face Rotate, ▲▼ 가 Group Rotate 입니다.

이 둘은 시뮬레이터 디스크를 다룹니다(preset.save·preset.load) — 위 드롭다운의 save/3D/Preset(이 PC)과는 다른 곳입니다. 파일명은 위에서 고른 것을 씁니다.

배치

프리팹 목록의 정본은 config/car_catalog.json 입니다 — 배열 순서가 곧 prefabId(1부터)이고, 순서를 바꾸면 저장된 CarPos_*.json 의 차종 해석이 바뀝니다.

클릭 배치는 언리얼에 view.pick 신설이 필요합니다 — 지금은 자동생성(car.createLine)과 좌표 직접 입력으로 배치합니다.

차량 오브젝트 -

랜덤은 car.resetRandom 하나로 합니다. 시뮬레이터의 random.slotPlace·slotJitter·frontBack·randomizeAll 은 등록만 돼 있고 동작하지 않습니다.

카메라 리스트

카메라 프리셋은 시뮬레이터에 없습니다. cam.savePreset·loadPreset·applyPreset 셋 다 등록만 돼 있고 동작하지 않습니다(per-camera 프리셋 메모리 없음). 그래서 버튼을 만들지 않았습니다 — 눌러도 안 되는 버튼보다 없는 편이 낫습니다.

조명 설정 언리얼 RPC 미구현

이 툴은 아직 동작하지 않습니다. 시뮬레이터 RPC 서버에 light.* 가 등록돼 있지 않습니다 — 실측에서 -32601 미등록 method: light.get 이 돌아옵니다.

화면은 일부러 만들지 않았습니다. 부를 곳이 없는 입력칸을 그려 두면 값을 넣고 「적용」을 눌러도 아무 일이 안 일어나는데, 사용자는 적용됐다고 믿습니다.

시뮬레이터 뷰 정지

영상은 자동으로 시작하지 않습니다. 카메라를 고르고 「시작」을 누르세요.

지시 6의 「main 카메라」 스트림은 아직 없습니다. 시뮬레이터는 PTZ 카메라별 스트림(13600+camId)만 제공하고, 플레이어 뷰 스트림은 언리얼에 view.* + 전용 MJPEG 채널 신설이 필요합니다. 지금 보이는 것은 선택한 PTZ 카메라의 영상입니다.
